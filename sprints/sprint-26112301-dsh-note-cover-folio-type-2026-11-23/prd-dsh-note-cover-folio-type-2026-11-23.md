# 需求

## 1. 补充说明要能展开更多

现状：折叠态只露 2 行 + 「展开全文」；点击后便签在 in-flow 里只长到 260px 上限，正文区同时被压缩，用户读不完老师的整段说明。

要求：
- 竖排 feed（≤ 约 760px 画布）点击展开后，便签以覆盖方式向上生长，遮住上方「老师要求」正文是允许的——此时用户的目标就是读补充说明。
- 卡体高度与宿主 iframe 高度不变（否则会触发 Q 卡重新量高、底部落影错位）。
- 展开高度取内容高与可用空间（距纸面顶 −48px、硬上限 320px）的较小值；落定后便签正文自己滚，头部（标题 + 收起）钉住。
- 横排 1133 档卡高固定，便签 in-flow 长高、正文区收缩，不遮挡仍可滚动的正文。

## 2. 展开/收拢要有微动效

- 展开 240ms `cubic-bezier(.22,1,.36,1)`，收起 180ms `cubic-bezier(.4,0,1,1)`，只过渡 `height`。
- 动画中途再点要能反向（从当前高度续接），不能瞬跳、不能累积监听。
- `prefers-reduced-motion: reduce` 直接落定。
- 视口宽度或布局档位变化时复位到折叠态；iframe 自身量高引起的 `resize` 不得触发复位。

## 3. 票夹手机字号

- 画布宽 ≤480px：弹窗标题 18px、曲目名 16px、副行 13px、环节 pill 13.5px（36 高）、BPM 徽标 12.5px（30 高）、分类 pill 12.5px（32 高）、归档展开按钮 14px（44 高）。
- 1133 档保持 16 / 14 / 12 / 12 / 11.5。
- 放大后不得出现横向溢出，列表滚动区高度不塌陷。
