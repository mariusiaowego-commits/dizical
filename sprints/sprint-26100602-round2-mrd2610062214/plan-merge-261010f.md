# 并入计划 · 左栏票根件 + 右栏六卡 → 一整页（2026-10-10）

档位：**计划稿**（等你拍）。右栏本轮改好即定稿，下面是「怎么并、并完长什么样、按什么顺序、怎么验」。

## 一、并的两边各是什么（实测）

| | 左栏（现成） | 右栏（本轮） |
|---|---|---|
| 文件 | `docs/demos/practice-ticket-v4-260920.html` | `practice-right-column-261003/` 下 10 页 |
| 体量 | **171,435 B / 5,147 行**，单文件 | 6 张卡各一页 + 组合页 |
| 结构 | `main.pk-stage-wrap` → `aside.pk-left-col`（票头 / hero 框 / 科目块 / 数字步进 / stub 列 / prep-only 标签 / run-only 折叠块 / 日历 / 备忘 / 条码）+ `div.pk-main-col`（尺子 + 抽屉列表） | 6 卡：D1 仪表盘 / D2 节拍器(+v5 对照) / D3 底块 / D4 老师要求 / D5 今日记录 / D6 今日时长 |
| 配色 token | `--c-primary / --c-accent / --c-secondary / --c-tertiary / --c-muted / --c-neutral` + `--border-*` + `--cta-bg` + `--pk-*` | **`--dash-*` 77 名**（含 `--dash-coral*` / `--dash-vermilion*`） |
| 响应式 | **`@media`（视口）** 9 条 + `prefers-reduced-motion` | **`@container`（容器）** + 卡片契约 min/默认/max 宽 |
| 组合规则 | 单页内部两栏 | `compose-02.html` 已定：上宽 = 下两张合计；放不下降一行一张（阈值实测 656px） |

**结论**：真正的工作量不在「搬页面」，而在**两套 token 命名空间**和**两套响应式真值**要合成一套。卡本身不用重画。

## 二、四步走（每步独立可验、可回退）

### 步 1 · token 归一（先建映射表，不并存两套色值）
把左栏的 `--c-*` 映射到右栏 `--dash-*`，**值统一从 `--dash-*` 出**，左栏旧名保留为别名（一层 `var()`），避免一次改死 5,147 行。

| 左栏旧名 | 归到 `--dash-*` | 说明 |
|---|---|---|
| `--c-primary` | `--dash-coral` | 珊瑚第一主色（品牌与主行动） |
| `--c-accent` | `--dash-vermilion` | 朱橙第二主色（能量/进度/强度）—— 左栏原来只有「accent」一个名额，本轮拆成两支，**要人工看一遍每个用点该归哪支** |
| `--c-secondary` | `--dash-text` | 深蓝灰 → 文字主色 |
| `--c-tertiary` | `--dash-page` | 暖白 → 页底 |
| `--c-neutral` | `--dash-white` | 卡片底 |
| `--c-muted` | `--dash-text-soft` | 次级文字（**不可用 `--dash-muted` 当文字色**，既定约束） |
| `--border-card / -strong / -active` | `--dash-line / --dash-line-strong / --dash-vermilion-line` | — |
| `--cta-bg` | `--dash-coral-solid` | 白字压底必须用实心变体 |
| `--pk-*`（抽屉等） | 保留专名，只把**颜色**改成 `--dash-*` | 布局参数不动 |

验收：左栏页 `?audit=1` 出 `ASSERT_OK`，且三把尺子（`verify-demos.py` 契约名集合 / `token-contrast.py` / 浏览器 audit）在这个页上**全过**；色值 diff **只看映射表**，不出现手写 hex。

### 步 2 · 左栏件包成「第 7 张卡」接入槽位系统
- 给 `aside.pk-left-col` 加卡片契约：`min / 默认 / max` 三档宽 + 与其它 6 卡同一套外框（圆角 / 边框 / 内边距 / 阴影语言）
- 接进 `compose-02.html` 的槽位系统（作为「组合」里的主卡）
- 效果：**左右并排第一次真的能跑**——左栏票根 + 右栏仪表盘并排，中间 gap 与卡片契约一致，换档时两栏同时收放

验收：在 compose-02 三档宽（820 / 620 / 460）+ 三档视口（1133 / 744 / 440）下，左右两栏**等高 / 无横滑 / 无裁切 / 中轴对齐**，并打出实测宽高。

### 步 3 · 响应式真值合并到「容器」
- 左栏 9 条 `@media` 是**视口**真值，右栏卡是**容器**真值 → 同一屏两套真值必然打架（这在 compose-02 窄槽已出现过：视口 1133 但槽只有 428）
- 统一原则：**容器宽为唯一真值**；`@media` 只保留「整页级」判定（要不要整页纵排、要不要隐藏非核心块）
- 左栏块内所有断点改写成 `@container`，与卡片契约同一套阈值

验收：把左栏卡塞进 428px 的槽（compose 组合1 460 档）时，它自己按容器降级（不再按视口显示成宽版）；三档视口下页面**无横滑**，实测容器宽与断点命中情况逐条打印。

### 步 4 · 组合规律升级为整页布局
- 把 `compose-02` 的组合1（上卡 + 下两张）/ 组合2 规律推广成**整页规则表**：主列（左栏票根）+ 右栏 N 卡，按容器宽决定列数（3 列 / 2 列 / 1 列）
- 「放不下就降一行一张」这条**从卡内推广到整页**（有实测阈值，不用魔法断点）
- 效果：iPad 横屏=左栏 + 右栏 3 列；iPad 竖屏=左栏 + 右栏 2 列；手机=单列顺排，卡片先后顺序按重要性（计时 → 节拍器 → 时长 → 记录 → 要求 → 底块）

验收：三档视口 × 两皮肤，每档打「实际列数 / 每列宽 / 是否有横滑 / 卡片顺序」，且**负控**：把降级判定关掉必须报红。

## 三、并完长什么样（现象描述）

- **iPad 横屏（1133×744）**：左边一列票根（科目 + 数字步进 + 秒表 + 尺子），右边一屏六卡分三列排开；顶栏一条 demo 徽章；所有卡同圆角同描边同内距，扫一眼是「一屏仪器」而不是「六张不同来源的卡」。珊瑚只出现在主按钮与选中态，朱橙只出现在进度/强度/节拍灯——**一个主色主导，另一个当度量**。
- **iPad 竖屏（744×1133）**：右栏降成 2 列，D1 仪表盘独占一行，其余两两成对；左栏票根收窄但仍是一列。
- **手机（440×956）**：全部单列顺排，左栏票根在上（它是操作入口），六卡按重要性往下；节拍器 744 专用布局在窄屏走 440 档（甲板横向药丸）。
- 换皮肤（浅银 ↔ 深墨）时左右两栏**同时**翻转，不出现一边白底一边深底。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 左栏 `--c-accent` 一个名额要拆成珊瑚/朱橙两支，可能拆错 | 步 1 里**逐用点过一遍**并留映射注释；拆不准的先归珊瑚（保守），单独列清单给你看 |
| 两套 token 并存期色值漂移 | 值只允许在 `--dash-*` 定义；旧名一律 `var()` 别名，门禁禁止字面量 |
| `@media` ↔ `@container` 混用 | 步 3 统一；门禁加一条：页面内出现「按视口改卡内宽度」的 `@media` 即报红 |
| 左栏 171KB 单文件难切片移植生产 | 先在 demo 里并成**一页**定稿，再按块切（票头/hero/步进/stub/折叠块/尺子/抽屉）分 7 片移植 `practice.html` |
| 生产模板 `practice.html`（4,693 行）被误改 | 移植前不动生产；每次切片一次 PR，每片单独验证 |
