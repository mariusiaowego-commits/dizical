## 2. 移植与回归

- 移植顺序：卡片基础规范 → 模块逐个替换 → 每步跑 `tests/test_practice_timer_frontend.py` + practice 相关前端契约
- 打卡链路（`POST /api/log` / `practice_at` CST / 必填语义）逐字不变；必填体验改法是"预选默认 + 给原因"
- 断点收敛：8 个断点 → 手机 / 横屏 iPad / 竖屏 iPad / 桌面 四档以内（具体值随模块 demo 定）

## 3. 3D 沉浸式主视觉 — Phase 2 计划占位（dad D2 要求先建占位写明计划）

**本期不做 3D**（dad 拍板 Q1/D2 = A）。Phase 2 需要先解决的前置：

1. **资产**：每个科目一个可交互场景（笛身气流 / 音孔指法 / 竹林等），当前仓库零 3D 资产储备
2. **数据模型**：需要"场景状态 + 元素解锁"存储（现有 `daily_practices` 是扁平记录，无此结构）；每次练习给场景增添元素 = 需要解锁事件与幂等写入
3. **性能与可用性**：主设备 iPad 横屏；7:15 早课要求 0 秒冷启动、不白屏、无卡顿；WebGL 上下文内存压力要评估
4. **降级策略**：WebGL 不可用 / 低电量 / reduced-motion 时回退到 2D 主视觉（本期就产出的那套）
5. **落地顺序建议**：先一个科目做单场景原型 → 真机跑帧率 → 再决定是否铺到 10 个在用科目
6. **本期要为 3D 预留的东西**：中央主视觉的容器尺寸与位置契约、主视觉与控制区的分层（避免 3D 进来后卡片布局被迫重排）、主视觉的开关开关配置项

> 本段是占位计划，具体 PRD / 设计稿等 dad 提供参考后再补；届时另开 sprint（编号待定）。
