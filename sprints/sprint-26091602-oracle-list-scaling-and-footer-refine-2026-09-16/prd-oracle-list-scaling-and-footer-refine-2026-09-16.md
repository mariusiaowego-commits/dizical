# PRD · Oracle 典藏卡列表缩放与页脚细节优化

## 1. 需求背景与目标

PR #330 将 Oracle 典藏卡体系合入生产后，dad 在 `localhost:8765` 真机验收发现：卡面在**单卡 Modal 大尺寸**下观感良好，但在**卡墙列表态**（小尺寸）下出现一系列比例与框架问题 —— 名牌过高遮挡人物原画、胸针/印章/头像偏大、页脚类别名冗长且头像 hardcode、卡片外层残留白底框、Modal 内锁标遮住卡背典故、成就页列表过长、静态资源缓存未刷新。

随后 dad 又追加两轮打磨：名牌文字左对齐、立绘重心微调、卡墙网格自适应多列、懒加载与闲置降帧，以及成就页展示数量由 3 张调整为 5 张。

### 核心目标

- 让**列表态**卡面的视觉重心回到人物原画（而非名牌/装饰件）
- 建立「类别 → 单字 + 头像」的动态映射，去除 hardcode
- 清除卡片外层冗余白框，使卡面直接坐在页面上
- Modal 详情态不遮挡典故内容
- 卡墙布局自适应，并降低列表闲置时的渲染开销

### 成功标准

dad 真机目视验收通过（三轮），全量回归零失败，PR 合入 main。

## 3. 功能需求

### 3.1 列表态名牌与装饰件缩放（首轮 1、2）

- `.oracle-nameplate` 列表态收紧高度、内边距与字号，不再遮挡人物原画
- `.oracle-pin`（胸针）、`.oracle-seal`（印章）、`.oracle-avatar`（类别头像）按卡宽等比收缩至 ~15–16px 比例

### 3.2 类别 → 单字 + 头像动态映射（首轮 3）

| 类别 | tag | 单字 | 头像 |
|------|-----|------|------|
| 突破 | 突破 | 破 | 随类别动态 |
| 巅峰 | 巅峰 | 极 | 随类别动态 |
| 执着 | 执着 | 韧 | 随类别动态 |
| 段位 | 段位 | 阶 | 随类别动态 |
| 晋级 | 晋级 | 跃 | 随类别动态 |
| 神秘 | 神秘 | 秘 | 随类别动态 |
| 主题 | 主题 | 典 | 随类别动态 |

彻底移除 hardcode 的「晨晨」。

### 3.3 卡片外层白框清除（首轮 4）

- `badges.html` `.badge-card`、`achievements.html` `.b-card` 双清：`background: transparent` / `border: none` / `padding: 0` / `box-shadow: none`
- `.b-card` 侧必须**排除盲盒** `#card-daily-blindbox .b-card`（盲盒视觉是圆形头像，与徽章卡无关）

### 3.4 Modal 锁标隐藏（首轮 5）

- 锁定卡片在详情 3D Modal 放大及翻转时隐藏锁标，避免遮挡卡背典故

### 3.5 成就页展示数量限制（首轮 6 + 三轮 12）

- 已解锁列表仅展示**最近 5 张**（三轮由 3 张调整）
- **保留完整总数统计**与查看全部入口

### 3.6 资源版本统一（首轮 7 + 二轮 10）

- cache-buster 统一升级，4 个引用点同步：badges.html / achievements.html / _badge_claim_modal.html / oracle_production_audit.html
- 首轮 `?v=26091602` → 二轮 `?v=26091603`

### 3.7 名牌左对齐 / 立绘重心（二轮 8、9）

- 名牌文字改为左对齐（原居中显松散）
- 立绘重心微调，构图更居中

### 3.8 卡墙网格自适应多列（二轮 10）

- 手机 2 列；宽屏按 ~160px 黄金卡宽 `auto-fill` 自动铺满（原为固定断点）

### 3.9 懒加载与闲置降帧（二轮 11）

- 卡面 `<img>` 加 `loading="lazy"` + `decoding="async"`
- 列表墙默认 `idleSkip=4`（≈15fps 闲置漂移）；hover / interacting 走满帧；focus / modal 保持 60fps

## 4. 非功能需求

- **性能**：降低列表闲置渲染开销，不引入新依赖
- **兼容**：iPad mini Safari / Mac Safari / Chrome / mac app WKWebView
- **隔离**：仅改前端静态资源与模板，后端与数据库零改动
- **无障碍**：装饰元素保留 `aria-label`；Modal 保持 `role="dialog"` + `aria-modal`

## 5. 非目标（明确不做）

- 不改后端 API 契约、不动 `achievements` 表结构
- 不新增 npm / pip 依赖
- 不重构 3D 几何参数基线
- **不做「加载慢」的整体性能优化** —— dad 明确指示另开专项 sprint
