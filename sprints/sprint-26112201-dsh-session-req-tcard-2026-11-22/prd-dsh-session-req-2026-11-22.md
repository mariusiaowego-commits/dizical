# PRD · 老师要求环节化与 Q/T 卡重构

## 背景

dad 261122 提 5 组问题：

1. 老师要求里第一条要求被渲染成大标题，层级错了；大标题应是每个练习环节。
2. 每个科目每次练习有不同 session；session 应是 `/config/practice` 可录入的预置环节，含要求描述与结构化 BPM。BPM 要能联动节拍器和练习记录。
3. 多次出现「session 要求写了 BPM，练习时还是 ♪=80」。
4. Q 卡上一张/下一张按钮点击没有动画，只有拖拽有。
5. Q 卡高度应与其它卡一致；上一张/下一张与进度点应进卡内独立区域；卡顶圆角缺描边。
6. T 卡（D 今日时长 + R 今日记录拼壳）需重构：有美感、功能不与其它卡重复。

## 需求

- 预置环节：`/config/practice` 每个科目可录入 ≤20 个环节，字段名称（≤50 字）、BPM（40–200，可空）、音符（♩/♪/♬）、环节要求（≤200 字）。
- 老师要求：`/config/practice-log` Tab2 每条科目要求可带环节列表；选科目时自动带出该科目预置环节；提交落 `sessions`，老字段 `metronome`/`requirements` 同步聚合。
- 练习助手：选中环节立即把 BPM/音符写入节拍器与练习记录载荷；手输自定义内容不覆盖手动调的速度。
- Q 卡：环节名做小标题，环节 BPM 用胶囊显示；不再出现全局「速度」行与环节速度打架；底栏在卡内。
- T 卡：原生渲染今日时间轴，卡高锁到票卡高，窄档保持整卡。

## 验收标准

- 选 `80乐段 ♪=98` 时载荷 `tempo_bpm=98 / tempo_note=♪`，不再 80。
- 1133×744 下 A/B/Q/T 卡高均 744；Q 底栏 `card.contains(foot) === true`。
- Q 卡 `border-width=0`、`::before` 1px 描边，深浅皮肤各自可见。
- 点击上一张/下一张与指示点在 90ms 内出现位移/旋转/透明度变化。
- 配置页可增删环节并保存后 GET 回读一致；非法 BPM 返回 400。
