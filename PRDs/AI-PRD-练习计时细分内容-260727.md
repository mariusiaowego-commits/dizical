## §1 背景

`daily_practices.items` 是按"科目维度汇总"的 JSON，结构是 `[{item, item_id, minutes}]`；`save_daily_practice` 的合并逻辑是"同 item 累加 minutes"（`src/database.py:757-784`）。这跟需求描述的"西藏舞曲 5min 练第一分句/♩=80，3min 练第二分句/♩=80"天然冲突：

- 同科目第 2 次计时会被合并成单条 8 分钟，看不出"5+3"。
- 没有"速度"和"细节内容"字段，前端 `submitPractice()` 也只传 `item + minutes`（`src/kid_app/templates/practice.html:1443-1502`）。
- `behavior_log` 是 audit 用途，不能当 session 真相用，否则污染审计语义。

**6-22 MRD**（`PRDs/mrd-每天练习新增练习场次｜新增加速模式（对应日常模式）｜新增每一次科目练习明细及配套前后端需求.md`）已经描述过完整需求但**没做**。本次只切**最核心一块**（"每次科目计时细分内容"），剩余 3 块推迟到 V2。

## §2 目标 (Goals)

1. 每次计时生成一条独立 session，能区分"同一科目当天多次练习的不同内容"。
2. Session 携带**练习速度**（音符 ♪/♩ + BPM 40–150）和**细节内容**（用户手动输入的短文本）。
3. 现有 `daily_practices.items` 汇总逻辑继续工作，**老成就 / 老报表 / 小程序不回归**。
4. 今日练习记录从"科目 + 总分钟"扩展为"科目汇总 + 多行 session 细节"展示。
5. 配置补录支持录入/编辑 session 细节。
6. 所有改动走 PR 流程：测试 + 文档 + 收尾 checklist + API-CHANGELOG + Obsidian 镜像。

## §3 非目标 (Non-Goals)

- **不做**"一天 N 场练习"分段（6-22 MRD 第 1 点）—— V2
- **不做**AI 自动摘要（6-22 MRD 第 5.(2) / (3)）—— V2
- **不做**"加速模式 / 日常模式"切换（6-22 MRD 第 2-3 点）—— V2
- **不做**语音转文字录入（dad 7-27 明确取消）—— V2 视情况

- **不动 dizical-minip**（变更分类为 🟡 部分兼容，minip 可暂不改；评估后写入 changelog）
- **不动旧 `daily_practices` 字段**（`items` JSON 仍是每日汇总；session 是新事实表，不替代它）

## §4 用户故事

### US-1: 家长在 practice 页录入带细节的一次计时

- 进入 `/practice` → 选科目"西藏舞曲" → 在主计时面板内看到"本次练习"区
- **速度默认值自动填**（按 Q1=B 规则）：取该 item_id 的"最近一次 session"或 fallback 到 assignment metronome
- 输入细节"第一分句连吐"
- **提交按钮初始 disabled**（按 Q3=A 规则：必填项未填完 disabled）
- 填完细节后按钮 enabled → 按"开始"→ 计时跑完 → 弹完成提示 → 提交
- 后端保存 1 条 session，daily 总览 +5 分钟
- **计时中 input 仍可改**（按 Q2=A 规则：边练边改）
- 继续计时 → 改内容"第二分句换气" → 提交 → 第 2 条 session
- 今日记录显示："西藏舞曲 8 分钟 · 2 行细节"

### US-2: 家长手动输入细节（不依赖语音）

- 细节输入是普通 `<input type="text">` + 提交前/计时中可改
- 不需要任何外部服务
- **内容必填**（按 Q3=A 规则）：空字符串时提交按钮 disabled，避免"未填写练习内容"提交
- 切换科目后输入框清空（V1 简化：清空）

### US-3: 今日记录展示

- 列表项按"科目"分组，组头显示汇总分钟
- 组内按 session 时间升序列出每条："5 分钟 · ♪=80  第一分句连吐"
- content 为空显示"未填写练习内容"，不伪造文案
- 删除针对单条 session；旧数据无 session 时保留旧"按 item_id 删整科目"行为，标"历史汇总"

### US-4: 配置补录（config-practice-log）

- 补录每行增加"内容"+"音符"+"BPM"，复用同一写入路径
- 旧数据无 session 时可保存为"空内容"session
- 补录时间继续走 CST `practice_at` 规则（不破坏现有补录语义）

### US-5: 旧数据兼容 + 迁移

- 跑幂等迁移：把现有 `behavior_log` 里 `[{enter_time, item, item_id, minutes}]` 拆成 session 行
- 旧数据 `tempo_note='♪'`、`tempo_bpm=80`、`content=''`、`content_source='legacy'`
- 不猜内容、不猜真实速度
- 迁移 marker 防重跑
- 迁移前生成 SQLite 备份（沿用项目 `backup.py` 模式）

## §5 数据模型

### 新表 `practice_sessions`

```sql
CREATE TABLE practice_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    practice_date DATE NOT NULL,
    item_id INTEGER NOT NULL,
    item_name TEXT NOT NULL,                -- 名称快照，科目改名后历史不失真
    duration_minutes INTEGER NOT NULL,      -- 实际计时分钟（向上取整）
    tempo_note TEXT NOT NULL DEFAULT '♪',   -- 只接受 ♪ / ♩，白名单校验
    tempo_bpm INTEGER NOT NULL DEFAULT 80,  -- 40–150，越界拒绝
    content TEXT NOT NULL DEFAULT '',       -- 细节短文本，可空
    content_source TEXT NOT NULL DEFAULT 'manual',  -- manual / legacy
    is_extra BOOLEAN NOT NULL DEFAULT 0,
    started_at TEXT,                        -- CST ISO 无 Z，与项目既有 practice_at 格式一致
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (item_id) REFERENCES practice_items(item_id)
);
CREATE INDEX idx_practice_sessions_date ON practice_sessions(practice_date);
CREATE INDEX idx_practice_sessions_item_date ON practice_sessions(item_id, practice_date);
```

### 与 `daily_practices` 关系

- `daily_practices` **继续是每日汇总**：items JSON 累加 minutes、`total_minutes` 同步更新、`practice_at` 仍按既有逻辑。
- `practice_sessions` **是事实表**：每次计时 1 行。
- 写入走同一事务：`save_practice_session_and_daily_summary()` BEGIN IMMEDIATE → 插 session → 更新 daily 汇总 → append audit → COMMIT。任一失败全部回滚。
- 删除 session 走同一事务重算 daily 汇总，避免负数 / 不一致。

## §5.5 前端交互规则（2026-07-27 dad 拍板 3 决策）

### 决策 1：速度默认值优先级（Q1=B）

选科目后，"本次练习"区的速度字段自动填，按以下顺序取：

1. **最近一次 session**（该 item_id 在 `practice_sessions` 表里 `created_at` 最新一条）→ 用其 `tempo_note` 和 `tempo_bpm`
2. **最近一次 assignment**（`weekly_assignments.items[].metronome` 含音符+BPM，例 `♩=82`）→ 正则解析后填
3. **硬编码 fallback** `♪ / 80`

切科目时触发重算。手动选过音符/BPM 后，本次 session 不再重算（避免覆盖用户输入）。

### 决策 2：计时中 input 始终 enabled（Q2=A）

`本次练习` 面板的音符/BPM/内容输入框：

- 选科目后填默认值，**editable**
- 计时开始后**仍 editable**（用户可边练边调整细节/速度）
- 计时结束弹完成提示时**仍 editable**（最后确认窗口）
- 提交动作取用户最后状态的值

不冻结、不禁用、不取计时开始时的快照。

### 决策 3：前端 disabled 必填门槛（Q3=A）

提交按钮（开始计时 + 结束打卡）disabled 状态机：

```
disabled = (selectedItemId == null)
        OR (content.trim() === '')     // 必填
        OR (tempo_note ∉ {'♪', '♩'})  // 默认 ♪ 必命中
        OR (tempo_bpm < 40 OR > 150)   // 默认 80 必命中
```

- 必填项未填完 → 按钮 disabled
- 填完 → 按钮 enabled（不再做后端 400 强校验，节省一次往返）
- 后端**仍做相同校验**（防绕过）但错误信息不向用户展示，仅写日志

### 后端兜底校验

- 校验白名单 ♪/♩
- BPM 40–150
- minutes > 0
- content 长度 ≤ 200
- 任一失败 → 400，错误写 audit log

## §6 API 合同

### 修改

- **`POST /api/log`** 新增可选字段：`tempo_note`、`tempo_bpm`、`content`、`content_source`。旧请求仍走兼容逻辑（生成 content 空 + content_source='manual' 的 session）。响应增加 `session` 对象。

### 新增

- **`GET /api/practice-sessions/{date}`** — 返回某日全部 session，可选 `?item_id=` 过滤。
- **`DELETE /api/practice-sessions/{session_id}`** — 删单条 session 并重算 daily 汇总，写审计。

### 不改

- `practice_audit_log` 字段 — 后端用新结构 append entry，客户端不再传 `behavior_log` 作为唯一事实。
- `dizical-minip` 暂时不动（评估后写入 changelog）。

## §11 V3.1 UI/UX 升级（练习页效率优化）

> **新增 2026-07-28 dad 需求**：练习页卡片合并 + session-panel 效率提升 + 补录分离 + 旋钮阻力

### 11.1 背景

用户实际使用后发现 4 个效率痛点：
1. 老师要求卡片与 item-section 卡片信息重复（科目名 + id 出现两次），占用空间
2. session-panel 速度输入需要弹键盘，太慢；内容每次都要打字，没有常用选项
3. 计时器与 session-panel 是两张独立卡片，视觉不统一
4. 补录页与练习页复用同一套组件，逻辑混乱有很多 `if (isRecall)` 判断
5. dial-knob 旋转到特定数字很累，没有阻力/吸附感

### 11.2 目标设备

**只优化 Web 端，两套目标设备**：
- MacBook Pro 16 寸（网页端）
- iPad mini（Safari 网页端）
- Mac app（WKWebView，与 Web 同一份代码，自动生效）

不优化小程序端（V2 视情况）。

### 11.3 卡片合并（P0）

**现状**：两张独立卡片 → item-section（科目选择） + floor-req（老师要求）

**问题**：
- `req-content` 中有科目名称和 item_id，与上面重复
- 两张卡片间距浪费空间
- resel-btn 位置不合理

**新设计**：合并为一张卡片

### 11.7 dial-knob 阻力点（P1）

**问题**：用户反应旋转旋钮到 5/10/15/20/25/30 这些常用值很累

**解决方案**：加吸附函数
- 在 5/10/15/20/25/30 这 6 个点 **±0.5° 内强吸附**（直接跳）
- **±1° 内弱吸附**（阻尼系数 0.3，旋转变慢）
- 离目标值 >1° 正常线性旋转
- 不影响自由旋转，只是在常用值附近有"卡一下"的手感
- 实现：JS 计算旋转角度 → 过吸附函数 → 映射到 minutes
- 配合 CSS `transition-timing-function` 实现阻尼视觉效果
