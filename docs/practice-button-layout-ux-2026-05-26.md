# Practice 科目按钮排列排布 — UX 专项诊断

> 日期：2026-05-26
> 文件：`src/kid_app/templates/practice.html` + `src/kid_app/app.py`
> 目标用户：8岁儿童 + 辅助家长

---

## 一、现状全景

### 数据事实
- **活跃科目**：11个
- **分类分布**：曲子 6个 | 演唱 2个 | 基本功 2个 | 分析 1个
- **归档科目**：约 10+ 个
- **分类总数**：8个（基本功/分析/演唱/单音/小节/句子/曲子/上课），其中 4 个分类下当前**无活跃科目**

### 当前实现
```
┌─────────────────────────────────────┐
│ 🎵 选择练习项目                       │
│ 🔍 搜索...                           │
│                                      │
│ 基本功                                │
│ [全按作低音re] [全按作低音re-音阶]     │  ← 2个按钮，占一整行
│                                      │
│ 分析                                  │
│ [吸气长音]                            │  ← 1个按钮，3/4空着
│                                      │
│ 演唱                                  │
│ [唱茉莉花（二）] [唱萨利哈]            │  ← 2个按钮
│                                      │
│ 曲子                                  │
│ [单吐练习] [回娘家] [采茶扑蝶]         │
│ [茉莉花（二）] [颤音练习] [萨丽哈]     │  ← 6个按钮
│                                      │
│ 📁 老科目                             │
└─────────────────────────────────────┘
```

Grid: `repeat(4, 1fr)` — 每行4列固定

---

## 二、核心问题

### 🔴 P0：信息密度极低，大量留白浪费屏幕

**问题**：4列 Grid + 按分类分块 = 大量空位

| 分类 | 科目数 | 占行数 | 空位数 |
|------|--------|--------|--------|
| 基本功 | 2 | 1 | 2个空 |
| 分析 | 1 | 1 | 3个空 |
| 演唱 | 2 | 1 | 2个空 |
| 曲子 | 6 | 2 | 2个空 |
| **合计** | **11** | **5** | **9个空位（45%浪费）** |

加上每个分类标题本身占一行，5行按钮 + 4行标题 = 9行空间放11个按钮。

**对孩子的影响**：iPad 上需要滚动才能看到曲子类，而曲子是最高频的练习科目。

---

### 🔴 P1：分类标题对儿童无意义

**问题**：8个分类中 4 个当前无活跃科目（单音/小节/句子/上课），剩余 4 个分类标题是**成人视角的技术术语**：

- "基本功" vs "分析" — 孩子不理解"分析"是什么意思
- "曲子" — 最直观，但混了"颤音练习"和"单吐练习"（这不是曲子）
- "演唱" — 只有 2 个，且名称"唱茉莉花（二）"与曲子里的"茉莉花（二）"高度混淆

**对孩子的认知成本**：需要先理解分类逻辑 → 再在分类下找科目 → 多层嵌套选择。8岁孩子更习惯"一眼看到我要练的东西"。

---

### 🟡 P2：颜色无信息量，纯装饰且混淆

**现状**：5种颜色按 `nth-child(5n+x)` 循环分配

```
青  粉  紫  橙  绿  青  粉  紫  橙  绿  青
```

**问题**：
- 颜色和分类无关（同分类的科目颜色不同）
- 颜色和难度无关
- 颜色和老师要求无关（老师要求另有金黄色覆盖）
- 视觉噪音大，11个按钮5种颜色 = 彩虹调色盘
- 有老师要求的科目强制变金黄，覆盖了原有颜色，两种颜色逻辑打架

---

### 🟡 P3：按钮内信息冗余

**现状**：按钮文字 = `科目名 [item_id]`

```
全按作低音re [1031]
```

**问题**：
- `[1031]` 是数据库主键，对用户零价值
- 用 `rgba(255,255,255,0.6)` 浅色显示 = 开发者自欺（"淡一点用户就看不见了"）
- 占据按钮宽度，挤压真正有用的科目名
- 儿童用户完全不懂数字ID的含义

---

### 🟡 P4：名称相似科目易混淆

```
曲子: 单吐练习 / 颤音练习 / 茉莉花（二）
演唱: 唱茉莉花（二） / 唱萨利哈
曲子: 萨丽哈
```

- "茉莉花（二）"和"唱茉莉花（二）"—— 傻傻分不清
- "萨丽哈"和"唱萨利哈"—— 同一首歌，吹 vs 唱，仅一字之差
- 没有任何视觉区分辅助（图标、前缀标签等）

---

### 🟢 P5：搜索框位置和形态不合理

**现状**：搜索框在科目网格上方，占一整行，placeholder 是 `🔍 搜索...`

**问题**：
- 11个科目不需要搜索。搜索是给几十上百个选项用的
- 搜索框占用了宝贵的首屏空间
- 对儿童来说，打字搜索比滚动点击更困难
- 搜索框的视觉权重（一整行 input）和它的实际价值不匹配

---

### 🟢 P6：归档科目的入口隐蔽但危险

**现状**：底部一个 `📁 老科目 (N)` 虚线按钮，点击展开归档列表

**问题**：
- 位置在最底部，不容易发现（好事）
- 但归档科目可以正常选中并打卡（坏事）—— 不该让已归档的科目产生新记录
- 归档科目样式（灰色删除线）和活跃科目视觉差异不够大

---

## 三、推荐方案

### 方案 A：扁平化 + 视觉分组（推荐 ⭐）

**核心思路**：去掉分类标题行，所有科目扁平排列，用颜色/图标区分类别

```
┌─────────────────────────────────┐
│ 🎵 选择练习项目                   │
│                                  │
│ ┌──────┐ ┌──────┐ ┌──────┐      │
│ │🎵茉莉│ │🎵回娘│ │🎵采茶│      │  ← 曲子：音符图标+蓝绿
│ │花（二）│ │家    │ │扑蝶  │      │
│ └──────┘ └──────┘ └──────┘      │
│ ┌──────┐ ┌──────┐ ┌──────┐      │
│ │🎵萨丽│ │🎵单吐│ │🎵颤音│      │
│ │哈    │ │练习  │ │练习  │      │
│ └──────┘ └──────┘ └──────┘      │
│ ┌──────┐ ┌──────┐ ┌──────┐      │
│ │🎤唱茉│ │🎤唱萨│ │🔧全按│      │  ← 演唱：话筒图标+粉色
│ │莉花  │ │利哈  │ │作re  │      │  ← 基本功：扳手图标+绿色
│ └──────┘ └──────┘ └──────┘      │
│ ┌──────┐ ┌──────┐               │
│ │🔧音阶│ │💨吸气│               │  ← 分析：风图标+紫色
│ └──────┘ └──────┘               │
└─────────────────────────────────┘
```

**关键变化**：
1. **3列 Grid**（从4列改3列）—— 按钮更宽，文字更易读
2. **去掉分类标题**—— 用按钮内图标+颜色区分，省掉4行空间
3. **科目排序**：高频在前（曲子→演唱→基本功→分析）
4. **同类别颜色一致**，不再 nth-child 循环
5. **移除 `[item_id]`**
6. **易混淆名称加前缀**："吹 茉莉花" / "唱 茉莉花"

**效果**：从9行压到4行，首屏即可看完所有选项

---

### 方案 B：保留分类但优化排版

如果坚持要分类，做以下调整：

1. **Grid 改 3列**，按钮更宽
2. **空分类不显示标题**（当前4个空分类的标题会占位）
3. **分类标题改为单行 inline 样式**（不用 h3 占一整行）
4. **分类可折叠**，默认只展开"曲子"
5. **移除 `[item_id]`**

**效果**：从9行压到约6行，改善但不彻底

---

### 方案 C：高频/低频两区

```
┌─────────────────────────────┐
│ ⭐ 今日必练                   │  ← 有老师要求的科目
│ [茉莉花（二）] [全按作re]      │
│                              │
│ 📚 更多科目                   │  ← 其余
│ [回娘家] [采茶扑蝶] [萨丽哈]   │
│ [单吐练习] [颤音练习] ...     │
└─────────────────────────────┘
```

按"老师有没有要求"分区，而非技术分类。更贴近孩子的认知路径：老师让我练什么 → 我还额外想练什么。

---

## 四、具体细节建议

| 项目 | 当前 | 建议 |
|------|------|------|
| Grid列数 | 4列 | 3列（按钮更宽，文字不挤） |
| 分类标题 | h3 独占一行 | 去掉或改为 inline tag |
| 颜色逻辑 | nth-child 循环5色 | 按分类着色（1类1色） |
| 按钮文字 | `科目名 [1031]` | `科目名`（去掉ID） |
| 搜索框 | 始终显示 | 11个科目不需要，移除或隐藏 |
| 老师要求 | 金黄覆盖原色 | 保留底色，加角标/徽章标记 |
| 易混淆名称 | 茉莉花（二）/ 唱茉莉花（二） | 吹·茉莉花 / 唱·茉莉花 |
| 归档科目 | 可打卡 | 只读展示，不可打卡 |
| 按钮尺寸 | 60px 高，13px 字 | 64px 高，15px 字（更适合儿童） |

---

## 五、移动端/iPad 特别注意

当前 `@media (max-width: 640px)` 只处理了三栏变单栏，**科目按钮区域没有任何响应式调整**：

- iPad 竖屏（768px）：4列按钮每列约 170px，中文3-4字刚好，但"全按作低音re-音阶"（10字）会被截断
- iPhone 横屏（667px）：4列每列约 150px，更紧张
- **建议**：768px 以下改3列，480px 以下改2列

---

## 六、总结

当前科目按钮区域最大的问题是**用成人的分类逻辑给8岁孩子做界面**——分类标题占空间、颜色无意义、信息冗余、排版稀疏。核心改进方向：

1. **压缩纵向空间**：去掉分类标题行，或改 inline
2. **颜色有意义**：同分类同色，而非循环
3. **去掉噪音**：删 `[item_id]`，删搜索框
4. **防混淆**：同名科目加"吹/唱"前缀
5. **响应式**：3列→2列自适应
