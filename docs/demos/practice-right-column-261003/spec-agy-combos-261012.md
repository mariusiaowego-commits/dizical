## 1. 核心高度与一屏基准线硬约束

### 1.1 高度等高硬约束（Dad MRD 第 7 条）
> “demo3.2的仪表盘，放到canvas里的时候，应该高度要和左边左栏的票夹一样，而不是像现在这样，高度很小。”

* **基准高度数值确定**：
  在 iPad 宽屏（1133px）及桌面（1280px）标准断点下，左栏基线票卡 `practice-ticket-v4-260920.html`（`#pkLeftCol` / `#pkTicketCard`）在准备态的标准高度为 **654px**（舞台 padding 16px，票卡底线位于 686px）。
* **硬规约**：
  **右栏的主视图总高度严格锁定为 654px，与左栏票卡 100% 顶边对齐、底边对齐！** 无论是单张大仪表盘，还是“仪表盘 + 底部卧卡”，其整体高度包络线必须严格等于 654px，坚决消灭旧版右栏高度坍缩、留白空洞的问题。

### 1.2 「一屏边界」物理法则（PDF 顶栏原话）
> “不论什么视口，如下虚线就是整个页面最右侧位置，过了此线右侧内容需要滑动才能查看”

* **一屏物理右界（Red Dashed Line）定义**：
  在标准 1133px（iPad 视口宽度）下，除去左右安全边距（左右各 16px ~ 24px），有效内容可视宽度为 **1085px**。
* **边界原则**：
  - 凡位于虚线左侧的内容，开屏即见，不得出现遮挡；
  - 凡跨越虚线的内容，作为次级扩展卡片，明确允许并通过轨道的横向平滑滚动（`overflow-x: auto`）查看。

## 5. 三档视口响应式退化规格

### 5.1 1133px 宽屏档（iPad 横屏 1133×744 / 桌面）
* **遵循规约**：完全执行上述第 2、3、4 节标准排版。
* **组合 1**：绝对一屏全显，无溢出，无横滑容器。
* **组合 2 / 组合 3**：前三列保持等高 654px，轨道容器 `overflow-x: auto`，右侧扩展卡平滑右滑。

### 5.2 744px 平板竖屏档（iPad 竖屏 744×1133）
* **画布状态**：画布由双栏并排自动转为**纵向上下分层**（`stageWrap` 的 `flex-direction: column`）。
* **票卡状态**：左栏票卡置顶，宽度拉满（744px 适配宽度，约 580px ~ 680px）。
* **右栏退化规则**：
  - **组合 1**：仪表盘全宽铺开（宽 580px，高 370px），下方两张卧卡（时长卡与记录小卡）继续以 1:1 并排平铺在仪表盘正下方；竖条节拍器退化为紧随其后的水平轻量控制条，或折叠为悬浮抽屉。
  - **组合 2 / 3**：卡片轨解除 654px 强限高，各卡片宽度统一收缩为 580px，支持纵向连续向下流式滚动，或者保留卡片轮播（Cards Carousel，每屏一张卡横向滑动）。

### 5.3 440px 手机极窄档（iPhone 440×956）
* **画布状态**：单列纯纵向流式（Single Column Vertical Flow）。
* **规约红线**：
  - **严禁在 400px 视口内强撑 2000px 的单行横滑长轨！**
  - 所有模块宽度自适应为 `100%`（约 380px ~ 408px）；
  - 模块按优先级垂直堆叠排布：`左栏票卡` $\to$ `卡槽` $\to$ `仪表盘` $\to$ `节拍器` $\to$ `今日记录小卡`；
  - 各模块内部 Demo 脚手架与调试条必须 `display: none !important`。

## 7. 按参考图基线校正（image20 / image23 / image24 逐图校对结论）

根据 `docs/demos/practice-right-column-261003/参考图文字基线-261012.md` 提取的真实几何读数，本规格做出以下关键校正：

1. **组合 1 仪表盘与卧卡高度黄金分割校正（对照 image23）**：
   - *原规格偏差*：原先设定仪表盘高 456px（占 70%），下方卧卡高 186px（占 28%），导致仪表盘偏大、卧卡偏扁；
   - *基线真值*：image23 读数明确指出“仪表盘高 ≈ 总高 1/2，宽:高 ≈ 1.2~1.3；下方两卡等高同宽”；
   - *校正结果*：仪表盘高度修正为 **370px**（与宽 460px 的宽高比为 1.24，精准落于 1.2~1.3）；下方两卡高度修正为 **268px**，整体严格填满 654px 总高包络线，比例完全符合 dad 参考图。
2. **组合 2 极窄节拍器与文字竖排校正（对照 image24）**：
   - *原规格偏差*：原先将竖条节拍器按组合 1 的 140px 标准宽度排布，且沿用常规水平文字排版；
   - *基线真值*：image24 读数明确指出“竖条节拍器第 3，极窄，宽 ≈ 高 × 1/8~1/10，**文字竖排**”；
   - *校正结果*：组合 2 中的竖条节拍器宽度大幅收缩为 **76px**（宽:高 ≈ 1:8.6），内部所有指示文本与 BPM 标签强制启用竖排排版（`writing-mode: vertical-rl` 或纵向单字栈流），释放出的横向空间让仪表盘与右侧今日练习卡获得更舒展的排版比例。
3. **票卡宽度与撕裂虚线截断相位自洽（对照 image20）**：
   - *基线真值*：image20 读数证实撕裂线本身为 `rgba(44, 62, 80, 0.2)` 极淡浅灰虚线，两端以完整实线段结束；dad 之所以判定两处“不一样”，是由于 canvas-01 宽屏（1133px）与原画布（1280px）票卡容器计算宽度产生 20px 偏差（360px vs 380px），导致虚线 repeat 截断相位发生偏移；
   - *校正规约*：在 1133 及以上宽屏视口中，左栏票卡外框宽度严格固化为 **380px**（或通过 SVG vector 虚线精确锁定两端 dasharray 相位），确保在任何断点下两端均保持整段闭合，根除 dad 指出的虚线断裂失真现象。
