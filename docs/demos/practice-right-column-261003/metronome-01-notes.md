## 一、 核心技术实现要点（含源码行号）

### 1.1 Lookahead 双时钟调度参数
在 `metronome-01.html:270-275` 中部署 Chris Wilson 双时钟模型：
- **粗粒度轮询周期**：`LOOKAHEAD_INTERVAL = 25.0 ms`（主线程 setInterval 唤醒频次，CPU 占用 < 0.2%）。
- **预读窗口（提前量）**：`SCHEDULE_AHEAD_TIME = 0.10 s (100 ms)`。
- **调度循环机理**（行 335-342）：当 `nextNoteTime < audioCtx.currentTime + 0.10s` 时，立即将未来 100ms 内即将到来的拍子排程到硬件音频队列，并以数学公式 `nextNoteTime += 60.0 / currentBpm` 严格递增。主线程即使发生 50ms 的 DOM 渲染或 GC 顿挫，声卡硬件发声也丝毫不受影响。

### 1.2 竹笛专用木质音色合成参数（非 440Hz 蜂鸣）
在 `metronome-01.html:310-335` 中使用纯振荡器与动态包络滤波合成仿生 Woodblock（木鱼/响棒）：
- **强拍 (Beat 1 - Downbeat)**：
  - 频率包络：`1200 Hz` 指数快速下潜至 `400 Hz`（耗时 `25 ms`）。
  - 增益包络：峰值 `0.42` 指数衰减至 `0.001`（耗时 `25 ms`）。
  - 声学特质：高亢干脆，穿透竹笛 85–95dB 的高频气鸣声。
- **弱拍 (Beats 2, 3, 4)**：
  - 频率包络：`600 Hz` 指数下潜至 `250 Hz`（耗时 `15 ms`）。
  - 增益包络：峰值 `0.20` 指数衰减至 `0.001`（耗时 `15 ms`）。
  - 声学特质：紧凑柔和，辅助打点而不抢主旋律。

### 1.3 iOS / iPadOS 四大限制应对方案落地
1. **规避静音开关 (Silent Switch Bypass)**（行 283-288）：
   - 在首次创建 `AudioContext` 时执行 `navigator.audioSession.type = 'playback'`（带有 `try/catch` 保护）。在 iOS 16.4+ 上将网页音频提升为媒体播放级别，物理静音开关开启时依然响亮发声。
2. **用户首次手势解锁 (Autoplay Policy)**（行 290-293、350-352）：
   - 在用户点击“启动节拍器”或首次触摸旋钮的同步事件回调中调用 `audioCtx.resume()`，彻底解锁 WebKit 的 `suspended` 限制。
3. **Screen Wake Lock 防息屏停摆**（行 296-308）：
   - 启动打拍时通过 `navigator.wakeLock.request('screen')` 申请屏幕常亮；停止打拍时调用 `wakeLock.release()` 释放。确保孩子练琴看谱期间 iPad 永不黑屏休眠。
4. **切后台回前台防暴风连环补发**（行 310-316）：
   - 监听 `document.addEventListener('visibilitychange', ...)`。当从后台切回前台时，若节拍器处于运行态，立即将时钟基准重置为 `nextNoteTime = audioCtx.currentTime + 0.05`，截断历史排程，防止 Safari 瞬间连珠炮补发滞后拍声。

### 1.4 大 Rotary Knob 真实嵌入尺寸与刻度处理
- **卡片内真实嵌入尺寸**：外径 `168px × 168px`（行 155，与 D1 `dashboard-skin-01.html:290` 的 `.knob` 完全 1:1 同规）。
- **空间与刻度处理**：
  - 在 168px 内部中心放置大字号读数（`42px` 粗体几何数字 + `11px` BPM 标签）；
  - 外圈围绕直径 `236px` 的同心 SVG 刻度环（40 级步进短刻度线，当前 BPM 以内高亮珊瑚红，外部呈半透明中灰）；
  - 旋钮转子边缘设计 `4px × 22px` 珊瑚红金属指针标记；
  - 触控支持：围绕中心角度的 `atan2` 极坐标旋转（左小右大，-135° 到 +135° 映射 40~240 BPM）；同时支持鼠标滚轮（wheel ±1）与键盘方向键（ArrowLeft/Right ±1）。

### 1.5 4 粒 Beat 指示灯余晖衰减（Phosphor Decay）
在 `metronome-01.html:110-145` 与 `375-395`：
- 不是粗暴的黑白硬切，而是模拟实体荧光管 LED：
- CSS 设定 `transition: background 0.04s ease-out, box-shadow 0.32s cubic-bezier(0.1, 0.8, 0.2, 1), transform 0.18s ease-out;`；
- 强拍触发时放大 1.18 倍并爆发 `0 0 16px var(--dash-coral)` 强光晕；发声后依据当前拍长动态淡出余晖（约 200–320ms），视觉流动感极强。

## 四、 本期未做项与下期规划理由

1. **拍号 4/4 切换**：
   - *现状*：内部固定 4/4 拍逻辑（每 4 拍循环一次强拍），未暴露 UI 切换开关。
   - *理由*：数据库 `assignments` 仅有 `tempo_bpm` 与 `tempo_note`，目前尚无拍号字段。若在 UI 上暴露选择，无法联动老师作业，且增加儿童触控干扰。
2. **`ACCENT: BEAT 1` 重音配置项**：
   - *现状*：代码层面默认第 1 拍为 Woodblock 强拍（1200Hz），其余为弱拍（600Hz），未提供界面抽屉来关闭或改设重音位置。
   - *理由*：儿童初学竹笛最需要均匀的重拍指引，无需让孩子自己去配置哪一拍打重音，保持操作零负担。
3. **TAP 测速键**：
   - *理由*：竹笛练琴 99% 场景是严格按照老师在作业中指定的 BPM（如 `♩=82`）慢练或原速练，极少需要孩子自行手指敲击测速，优先级后置。
4. **BPM 刻度尺 Slider**：
   - *理由*：避免与 top dark panel 已有的“练习时长 Ruler”在右栏发生严重的视觉冲突（双尺冲突）。大旋钮 + ±1 微调已经能完美覆盖所有调速需求。

## 五、 潜在风险与防御备忘

1. **iPad 多标签页并发运行时的音频冲突**：
   - *风险*：若孩子在 Safari 中打开了多个 Dizical 练习标签页并同时启动节拍器，会产生双重回声。
   - *防御*：在生产接线时，可在 `BroadcastChannel` 或 `localStorage` 中广播当前播放状态，确保同一浏览器实例内仅允许单实例发声。
2. **蓝牙耳机/外接音箱的物理延迟 (Bluetooth A2DP Latency)**：
   - *风险*：若 iPad 连接了老款蓝牙音箱，音频传输通常会有 100–200ms 的物理空口延迟，导致声学节拍声比屏幕上 4 粒 Beat 闪烁慢半拍。
   - *防御*：竹笛练习绝大多数为 iPad 自身扬声器外放（便于随身摆放）。若检测到音频输出延迟（通过 `audioCtx.baseLatency` / `outputLatency`），后续可加入微秒级视觉补偿对齐。
3. **长时间无操作时的系统资源回收**：
   - *风险*：Safari 在极低电量模式下可能会降低未被主动交互的后台定时器精度。
   - *防御*：`wakeLock` 保持屏幕高亮，且用户练习竹笛时处于高频视线关注状态，已把此风险降至最低。

## 七、 关于文件编码与显示乱码的实测排查结论

针对本手记文件在部分环境打开时可能出现中文乱码的现象，进行了底层二进制与编码严谨实测，结论如下：

1. **底层物理字节核验**：
   - 字节长度：`9925 bytes`，字符数：`5800 chars`，换行符：`137` 处纯 Unix LF (`\n`)，无任何 Windows CRLF (`\r\n`)。
   - UTF-8 BOM 探测：`raw[:3] == b'\xef\xbb\xbf'` 结果为 `False`（符合现代 Linux/macOS 标准无 BOM 规范）。
   - 严格解码测试：Python `codecs.decode(raw, 'utf-8', errors='strict')` **100% 成功，无任何解码异常或坏字节**。
2. **乱码诱因定位（客户端/终端读取环境问题）**：
   - 当使用强制以 `GBK` / `CP936` 解码该文件时：立即在位置 37（中文字符起始处）报 `illegal multibyte sequence` 错误；若强行宽容解析，GBK 会将 UTF-8 的 3 字节中文字符按每 2 字节组合为乱码生僻字（如 `閿` / `涓`）。
   - 当在 `ISO-8859-1` / `Windows-1252` 终端或未配置 UTF-8 语言环境（如缺少 `LANG=en_US.UTF-8`）的旧版编辑器中查看时，每个高位字节被直译为重音拉丁字母（如 `å`、`æ`）。
3. **处理策略与决策**：
   - 文件本身是**标准、合法的 UTF-8 编码**，内容完整健康，**严禁做任何破坏性转码或重写**。
   - 建议在终端中确认环境变量：`export LANG=en_US.UTF-8` 或在编辑器中将文件编码显式指定为 `UTF-8` 即可完美正常显示。
