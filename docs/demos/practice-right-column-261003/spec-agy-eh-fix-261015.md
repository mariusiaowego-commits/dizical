## 1. 核心常量与等高基准口径

### 1.1 基准高常量定义
- **桌面宽屏基准高（1133 档 / 1280 档）**：
  $$H \equiv h(\text{ticket})$$
  在当前 1133px 标准视口下，实测左栏票卡 `.pk-ticket` 的真实计算高度：
  $$H = 780\text{px}$$
  （注：舞台上下 padding 16px/32px，外框视口随内容及全屏状态自适应，以左栏票卡 DOM 计算值 $H$ 为右栏唯一法定标尺）。
- **宽屏铁律约束**：
  右栏中并排横列的每一个**独立列容器（Column Container）**，其总高度必须**严格闭合等于 $H$（误差 $0\text{px}$）**，顶边与票卡顶边平齐（$\Delta t = 0$），底边与票卡底边平齐（$\Delta b = 0$）。
- **窄屏（≤744 / ≤440）退化规则**：
  解除横向等高硬锁定，转为垂直单列自然流式（高度由卡片内容自适应计算，严禁在窄屏硬赋 $780\text{px}$，详见 `spec-agy-container-bp-261015.md`）。

## 3. Dad 问题 7 裁决：B 节拍器为什么没做同样高度？

### 3.1 现象根因分析
在旧实现中，Grok 将 B（340×520）与 D（340×248）垂直强行压进同一个列容器中（$520 + 12 + 248 = 780$），而右侧的今日记录卡 R 却单独占了一列全高（360×780）。  
这导致视觉感知极不协调：**B 作为主功能节拍器被腰斩缩水，而次要的记录卡 R 却通高拉长，大面积留白**。Dad 因而产生直观质问：“B 节拍器为什么没有做同样高度？”

### 3.2 两个重构方案对比

* **方案一（推荐并采纳）：B 独立成列通高（$H=780$）+ D/R 上下复合列**
  - **结构**：`[ A (通高 780) ] + [ B (通高 780) ] + [ D上 / R下 (复合列分高 780) ]`。
  - **优势**：
    1. 完美回应 Dad 第 7 条：B 节拍器与 A 仪表盘、左栏票卡完全同高（780px），表盘舒展大气；
    2. 完美落实 Dad 第 10 条原话：“今日记录卡和今日时长卡（D）一起组成一个时长/记录卡，上下结构。今日时长样式和位置不变，下面做今日练习记录卡”；
    3. 逻辑统一：所有组合中，只要出现 D 与 R，均采用统一的“时长在上、记录在下”的复合分高语法，降低心智负担。
* **方案二：纯扁平单卡全高横排（无任何上下堆叠）**
  - **结构**：`[ A (780) ] + [ B (780) ] + [ D (780) ] + [ R (780) ]`。
  - **弊端**：横向铺开 4 档大卡，总宽度将达 $430 + 340 + 360 + 360 + 48 = 1538\text{px}$。D 卡和 R 小卡内部只有少量信息，强行拉伸到 780px 造成极其空洞的视觉浪费，且直接违背了 Dad 第 10 条“D 和 R 上下结构”的明确要求。

**裁决结论**：采纳**方案一**。B 节拍器在组合 3 中独立通高（$H=780\text{px}$），D 与 R 在第 3 列执行上下分高（$460 + 12 + 308 = 780\text{px}$）。

## 4. 仪表盘 A 卡内自适应重排与消灭滚动条规范（Item 1.1 & 1.2）

### 4.1 滚动条溢出实测定位
实测 A 卡 iframe 内 body：`scrollHeight = 467px > clientHeight = 441px`，溢出 26px，出现丑陋的浏览器默认纵向滚动条。  
**溢出直接罪魁祸首**：
代码中使用了硬编码绝对定位与固定像素高容器：
- `#frame`: 固定高度 `height: 429px`，放置于 `top: 32px`，导致底部触达 $32 + 429 = 461\text{px} > 441\text{px}$！
- `#dash`: 固定 `width: 409px; height: 405px; top: 44px`
- `#panel`: 固定 `width: 377px; height: 115px; top: 58px`
- 底部诊断区 `.diag-card`: 固定绝对定位在底部，当卡片高度从 780 压缩到 440 时，绝对定位元素发生重叠碰撞并破框。

### 4.2 卡内分区比例规范（Flex 弹性垂直流）
彻底废除固定 `height: 429px` 与绝对定位 `top` 偏移。将仪表盘内部重构成**自顶向下 100% 弹性 Flex 容器**：

```css
.dash-card-body {
  display: flex;
  flex-direction: column;
  height: 100%;
  box-sizing: border-box;
  padding: 16px;
  overflow: hidden; /* 绝对禁止原生滚动条 */
}
```

内部四大逻辑区块的高度动态分配：
1. **顶部卡槽与状态区（Top Slot & Status Bar）**：
   - 占用高度：约 $40\text{px} \sim 48\text{px}$（固定紧凑高度）；
   - 包含拟物嵌入卡槽（与 A 卡顶边融合，详见 `spec-agy-slot-combo1-261015.md`）和精简状态灯。
2. **仪表主屏面板区（Master Gauge & Readout Panel）**：
   - 占用比例：`flex: 1 1 auto; min-height: 0;`（自适应吃满剩余空间）；
   - 在通高模式（$H=780$）下自然延展（约 $480\text{px}$）；在组合 1 分高模式（$H=440$）下收敛（约 $240\text{px} \sim 260\text{px}$）；
   - 表盘刻度、孔阵（.grille-6x8）、大号空心计时器数字（#ttCounter）基于弹性中心对齐。
3. **参数微调与操作栏（Controls & Sliders）**：
   - 占用高度：约 $56\text{px} \sim 64\text{px}$；
   - BPM 显示与调节按纽、音量滑块紧密行内排布。
4. **底部诊断诊断条（Bottom Diag Bar）**：
   - 占用高度：固定 $32\text{px}$（紧贴卡片底边内衬）；
   - 去除白底，直接融入底板；常驻精简状态点，长按或 hover 再弹出详情。

### 4.3 禁用的“写死坐标”清单（严禁出现在 A/B/D/R 中）
- ❌ 严禁使用固定框高：`#frame { height: 429px; }`
- ❌ 严禁写死纵向绝对定位：`top: 32px`, `top: 44px`, `top: 58px`, `top: 362px`
- ❌ 严禁固定高度面板：`#dash { height: 405px; }`, `#panel { height: 115px; }`
- ❌ 严禁在内嵌拟物卡片上出现 `overflow-y: scroll` 或 `overflow-y: auto`。

## 5. 可量判据（Price-Tag Verification Criteria）

本规范交付后的验收必须经由 Playwright 真实测量并出具价签：

1. **纵向无滚动条铁律**：
   对所有视口、所有组合下的仪表盘 A 卡内部 document：
   $$\text{doc.scrollHeight} \le \text{doc.clientHeight} \quad (\text{必须成立，溢出量 } \equiv 0\text{px})$$
   $$\text{getComputedStyle(body).overflowY} \ne \text{'scroll'}$$
2. **组合 3 B 节拍器全高闭合**：
   在组合 3（1133 档）中：
   $$h(B) = H \pm 1\text{px} \quad (\text{实测必须为 } 780\text{px})$$
   $$t(B) = t(\text{ticket}), \quad b(B) = b(\text{ticket})$$
3. **组合 3 D/R 复合列闭合**：
   $$h(D) + 12 + h(R) = H \pm 1\text{px} \quad (460 + 12 + 308 = 780)$$
   $$b(R) = b(\text{ticket}) \quad (\Delta b \equiv 0)$$
4. **组合 1 复合列闭合**：
   $$h(A) + 12 + \max(h(D), h(R)) = H \pm 1\text{px} \quad (440 + 12 + 328 = 780)$$
   底边与左栏票卡完全平齐（$\Delta b \equiv 0$）。
