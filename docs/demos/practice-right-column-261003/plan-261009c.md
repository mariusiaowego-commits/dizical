## 0 先回 dad 的三个问题（都有实测依据）

### Q「panel 圆盘外面多了一圈外框，上次改了什么？」
```
外框 = `.chassis-dome`：172×172 的银底凸拱（linear-gradient 由 --dash-shell-hi → lo）
        + 9:30 / 2:30 两个内凹圆角 `.panel-arch-fillet-*`（半径 14px，靠 box-shadow 造凹角）
它们不是这轮加的：`grep -c "chassis-dome|panel-arch-fillet" dashboard-skin-01-v2.html` = 0，
即【上一轮 v2.2（2026-10-08 round3）】引入的，当时的说法是「暗面板底边凹拱 + 银底盘凸拱包住旋钮上半」。
这轮（v2.3 / A+B）实际只做了三件事：① 30 点环半径收小贴旋钮；② 点段裁到 8:00–4:00；③ 读数提权 + 拱-尺间距 50.4 → 30.1px。
结论：你觉得「又变了」的外框是 v2.2 那轮的 dome —— 它是 172px，比点环 164px 还大 8px，所以点环外面确实多出一圈亮银环。
```
### Q「iPad / iPhone 视口整体没反应，是设计还是 bug？」
```
是「没做多视口」而不是 bug。D2 页有视口切换按钮（setViewport('ipad'|'iphone'|'fluid')，舞台框 1133 / 440 / 100%），
但卡片本身 `.card { max-width: 420px }`，全页只有一条 `@media (max-width:480px)` → 换视口只换舞台外框，卡片不重排。
这符合我们定的「卡片契约」：每张卡自己声明 min/默认/max 宽，dashboard 只负责排布。
处置（本轮）：给 D2 补 440 档的真重排（不是缩放），让换 iPhone 视口时真看得出差别；1133 档保持单列自然宽。
```
### Q「arc 为什么还是遮 ruler？」
```
实测（三档都一样）：`.ruler` 底 224 / `.arc`（30 点环）顶 254 / `.panel` 底 283 / `.chassis-dome` 顶 254。
   点环 vs 尺子盒子相交 = 0；但 dome/缺口 与 `.panel` 相交 4408px²（1133、440）/ 3762px²（744），即拱顶插进深色面板 29 / 19 / 29px。
推断（需 agy 用渲染像素复测确认）：`--arch-r: 86px`（JS 里写 `radius + 5`）是缺口半径，
   缺口顶点 = 面板底 283 − 86 = 197，**正好落在尺子行（192–224）里** → 尺子下半段的深色底被啃掉，看起来就是「arc 遮住 ruler」。
   换算：dome 圆面在面板底边上的开口宽 ≈ 2×√(86² − 47²) ≈ 144px。
所以「没改对」的根因不是点环，而是 **凹拱缺口半径太大 + 中段负 margin 把整块往上顶 -25.9px**（`.mid { margin-top: calc(var(--dash-notch) * -0.27) }`，notch=96px）。
```
