# PLAN — 节拍器音色与灯声同步（261008，只出方案，不写代码）

来源：`PRDs/MRD-节拍器音色.md`（2026-10-08）。dad 原话：用 Web Audio API，避开 setInterval 带来的延迟和抖动；内置 Woodblock、Digital Beep、Cowbell；鼓槌可选；声音必须和 4 粒灯同一瞬间亮；第一拍用重拍音色或提高音高。

现状（`metronome-01-v3.html`，不改，只作对照）：

- 声音已经写在 `audioCtx.currentTime` 的未来时刻上，lookahead 是 25ms 的 `setInterval` 去填 100ms 的队列。节拍点本身不靠 setInterval。
- 灯不在这个时钟上。`scheduleHit` 用 `setTimeout(delayMs)` 去点灯，余晖再用一个 `setTimeout` 熄灭。主线程一忙，灯就晚于声音。
- 音色是 5 个：木鱼 / 电子滴答 / 808 低鼓 / 鼓边 / 清脆 blip。包络被收成统一的 5ms 起、80ms 落，所以五个听起来偏近。
- 第 1 拍只是同一音色里略高、略响。`强弱拍` 开关默认关，关掉时第 1 粒灯用的是和弱拍一样的 `weak-lit`。
- 没有独立的 shared beat engine 文件。同一套 lookahead 在本页里一份，`dashboard-skin-01-v3.html` 里还有一份只负责「静音时不出声」的拷贝。

本方案不实现。下面 8 节是实现时要照的口径。

## 1. 四种音色怎么合成

全部用 Web Audio 现场合成，不加载采样。增益从 0.0001 指数升到峰值，再指数落回 0.0001，避免接上/断开时的爆音。第 1 拍走该音色自己的重拍行，不另换一种乐器（见第 4 节）。

| 音色 | 听感 | 振荡器 / 噪声 | 频率（弱拍 → 第 1 拍） | 包络 | 时长 |
|---|---|---|---|---|---|
| Woodblock 木鱼 | 低、木、短，像小木鱼敲一下，不刺 | 正弦下滑 + 一段很短的噪声。噪声过带通，中心 800Hz，Q 1.2，音量是正弦的 0.25 | 弱拍 720Hz 落到 200Hz；第 1 拍 980Hz 落到 260Hz | 起 2ms，落到近乎无声用 55ms。峰值 0.26 / 第 1 拍 0.40 | 80ms 停 |
| Digital Beep 电子滴答 | 高、细、钻，嘈杂房间里还能听见 | 正弦。不再加方波，避免和旧的 blip 抢同一块刺耳区 | 弱拍 2093Hz（C7）；第 1 拍 2637Hz（E7），音高固定，不下滑 | 起 1ms，落 28ms。峰值 0.16 / 第 1 拍 0.26 | 40ms 停 |
| Cowbell 牛铃 | 亮、金属、稍长，一声里有两个音高打架 | 两个方波，频率比约 1.44（弱拍 540Hz + 780Hz）。再过带通，中心 1400Hz，Q 4 | 第 1 拍两个音都乘 1.26（约高四度：680Hz + 980Hz） | 起 1ms，弱拍落 160ms，第 1 拍落 200ms。峰值 0.20 / 0.30 | 220ms 停 |
| Drumsticks 鼓槌（可选，建议做进选择器） | 干、木、更短，没有音高，像两根棍子相击 | 只有噪声。高通 2200Hz；再叠一层更轻的、带通 4000Hz 的噪声 | 无音高。第 1 拍把高通提到 2600Hz | 起 0.5ms，落 16ms / 第 1 拍 20ms。峰值 0.28 / 0.40 | 30ms 停 |

和现在五个的关系：

- 木鱼留下，按上表改配方。现在的木鱼从 980Hz 往下掉、再统一拉到 80ms，听感偏亮、偏长，对不上「低沉、温和」。
- 电子滴答留下，收成上面的短正弦。现在的 click 也是 80ms，所以它像一个短音，不像滴答。
- 牛铃是新的，不复用 808。808 是正弦从 150Hz 滑到 40Hz，那是底鼓，不是铃。
- 鼓槌替换现在的鼓边。鼓边是三角波加高通噪声，金属感更重；鼓槌只要木头的那一下。
- 清脆 blip 删掉。它的方波高频和电子滴答是同一个位子，留着选择器会多一个说不清的名字。

## 2. 调度

时钟只用 `AudioContext.currentTime`。节拍点是绝对时间，不是「过了多少毫秒再响」。

```
下一拍时刻 nextNoteTime
每帧：当 nextNoteTime < currentTime + 0.15 时
        把这一拍的振荡器 start(nextNoteTime)
        把 {time, beat, accent} 推进队列
        nextNoteTime += 60 / bpm
        beat += 1
```

- 预读深度 150ms。40 BPM 时一拍 1500ms，队列里通常只有 1 拍；200 BPM 时一拍 300ms，队列里最多 1 拍正在等待。150ms 够覆盖一帧卡顿，又不会在改速时留下一长串旧速度的拍。
- 填队列的循环放在第 3 节的 `requestAnimationFrame` 里，不再用 `setInterval(scheduler, 25)`。setInterval 的抖动以前不影响声音（声音有绝对时间），但 dad 点名要避开它。视觉循环已经每帧在跑，用它来填队列，少一个定时器。
- 中途改 BPM：已经 `start()` 的振荡器不动，它们会在原来的时刻响。还没排进去的下一拍用新的 `60 / bpm`。不把 `nextNoteTime` 拉回「现在」，否则会吞拍或叠拍。
- 中途改音色：只影响还没排进去的拍。150ms 内可能还有一声旧音色，这是有意的，不把已经排好的声音掐掉。
- 切到后台再回来：沿用现在的口径。不补后台漏掉的拍。`visibilitychange` 时 `resume()`，`nextNoteTime = currentTime + 0.05`，灯全灭，从下一拍重新排。
- 练习开始那一刻的快照不变：`sessionSnapshot` 仍是按下开始时的 `{bpm, timbre}`。后面拧旋钮、换音色，快照不动，只有耳朵里的下一拍变。

## 3. 灯和声音怎么保证是同一瞬间

声音的时刻是排进去的 `time`。灯不允许再算一个 `setTimeout(time - currentTime)`。

每一帧：

1. 读 `audioCtx.currentTime`，记为 `now`。
2. 按第 2 节把未来 150ms 的声音排完。
3. 在队列里找满足 `time <= now` 且 `now < time + glow` 的最后一拍。`glow = min(0.32, 0.7 * 60 / bpm)` 秒，沿用现在余晖的长度，但长度用在比较里，不另开定时器。
4. 这一拍是第几拍，就点亮 `#led0`…`#led3` 里对应的那一粒，其余熄灭。没有这样的拍，四粒全灭。

灯的亮起时刻因此是「第一个满足 `now >= time` 的动画帧」。在 60Hz 屏幕上，这一帧比声音晚 0 到 16.7ms，不会早。不使用 `setTimeout` 点灯或熄灯。

`?audit=1` 时引擎自己记两列时间，不靠人眼：

- `audioTime`：排给振荡器的 `time`
- `visualTime`：上面第 3 步第一次点亮该拍时的 `currentTime`

差 `visualTime - audioTime`。目标写在第 7 节。

## 4. 第 1 拍（重拍）和 4 粒灯

这一页的拍号固定 4/4，徽章已经写着「4/4 拍」。`beatsPerBar = 4`。灯的下标是 `beat % 4`。重拍是 `beat % 4 === 0`，也就是 `#led0`。

重拍规则（建议，见文末要 dad 拍板的 A/B）：

- 每一小节的第 1 拍都走该音色表里的「第 1 拍」行：音高更高或（鼓槌）更响、更亮。这与「强弱拍」开关无关，开关不再决定有没有重拍。
- `#led0` 用现成的 `accent-lit`（更亮）。其余三粒用 `weak-lit`。
- 现有的「强弱拍：关/开」若保留，只做一件额外的事：打开时，第 1 拍改用牛铃配方，不管当前选的是不是牛铃。关掉时，第 1 拍仍是当前音色的重拍行。默认关，这样竹笛练习不会每一小节被铃打断。

拍号以后若要 3/4、6/8，引擎的 `beatsPerBar` 可以变，但 DOM 仍是 4 粒灯。这次不改灯的个数，也不做拍号选择。

## 5. 选择器

现在是一排五个：木鱼、电子滴答、808 低鼓、鼓边、清脆 blip。改成四个，名字用 dad 的叫法，控件仍是现在的分段按钮，不新做一种控件。

| 钮上的字 | 内部 id | 来历 |
|---|---|---|
| 木鱼 | `wood` | 原「木鱼」，配方按第 1 节改 |
| 电子滴答 | `beep` | 原「电子滴答」，id 从 `click` 改成 `beep`，避免和点击事件混 |
| 牛铃 | `cowbell` | 新 |
| 鼓槌 | `sticks` | 新，替换鼓边 |

删掉 808 和 blip，理由见第 1 节。`localStorage` 键仍是 `dizical.metro.timbre`。读到 `sub808`、`blip`、`rim`、`click` 这些旧值时，落到木鱼，不报错。

## 7. 机器能判的验收

在 `metronome-01-v3.html?audit=1` 里跑，不靠耳朵。

同步（证明灯和声音是同一拍）：

- 方法：引擎在真实 `AudioContext` 上以 120 BPM 跑 32 拍。每一拍记下排给振荡器的 `audioTime`，以及 rAF 第一次把对应灯点亮时的 `currentTime`（`visualTime`）。差 = `visualTime - audioTime`。
- 目标：32 拍里至少 95% 的差落在 0 以上、20ms 以内；中位数 ≤ 10ms。0 是「不早于声音」。20ms 是 60Hz 一帧（16.7ms）再加一点余量。差为负说明灯亮早了，算失败。
- 这 32 拍期间，点灯路径没有调用 `setTimeout`。实现时给引擎一个计数器，审计开始前把 `window.setTimeout` 包一层只统计从 `paintLed` 发出的调用；期望是 0。包一层只存在于这次审计运行，不进正常播放。

重拍（证明第 1 拍不同）：

- 方法：同一段 32 拍，每拍记下 `beat % 4`、是否走了重拍行、以及该拍的峰值增益。
- 目标：`beat % 4 === 0` 的拍峰值严格大于相邻弱拍；这样的拍正好 8 个（32 / 4）。弱拍不得用重拍峰值。灯的一侧：这些拍点亮时 `#led0` 带 `accent-lit`，另外三粒不带。

另外保留现在已经在跑的几条，只改名字：四个音色钮都在；切换后 `currentTimbre` 变；预览让振荡器计数加一；快照在开始时冻结；`metro-card` 内 `.tick` 和 `.ruler-wrap` 仍是 0。
