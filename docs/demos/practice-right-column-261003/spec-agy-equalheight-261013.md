## 1. 等高铁律（Equal-Height Iron Law）

### 1.1 铁律定义与基准高度 $H$
根据 Dad 拍板原则：“左侧票夹也是一个‘卡片’，右侧仪表盘等卡片大家是一样高度的”。

* **基准高度 $H$ 定义**：
  右栏所有顶层列容器的基准高度 $H$，必须**严格等于**同视口档位下左栏票卡（`.pk-ticket` / `#pkTicketCard`）的实际计算高度：
  $$H \equiv h(\text{ticket})$$
* **三档视口实测高度取法**：
  1. **1133px 宽屏档（iPad 横屏 1133×744 标准）**：
     - 实测基准票卡高度：**$H = 559\text{px}$**（`.pk-ticket` computed: `360px × 559px`，舞台上下 padding 16px/32px）。
     - 右栏基准列高严格锁定为 **$559\text{px}$**。
  2. **1280px 桌面宽屏档（Mac / 桌面标准）**：
     - 实测基准票卡高度：**$H = 654\text{px}$**（`.pk-ticket` computed: `380px × 654px`）。
     - 右栏基准列高严格锁定为 **$654\text{px}$**。
  3. **744px 平板竖屏档（iPad 竖屏 744×1133）**：
     - 舞台转为上下折行（`flex-direction: column`），左栏票卡置顶，自然高度约 $520\text{px} \sim 559\text{px}$；
     - 右栏卡片进入轮播模式（Carousel）或按单卡 $H_{744} = 480\text{px}$ 保持卡片卡框等高横滑。
  4. **440px 手机极窄档（iPhone 440×956）**：
     - 舞台进入单列纵向流式（Vertical Flow），解除跨栏强行等高锁定；
     - 各卡片宽度 $100\%$，高度按内容最小高度自适应（`min-height: 280px ~ 360px`），禁止单行横撑 2000px。

### 1.2 顶格通高卡片清单与约束方程
凡独占一整列的卡片，必须**顶格通高**，顶边与票卡顶边平齐，底边与票卡底边平齐。

* **顶格通高卡片清单**：
  - `Card A`（全高仪表盘，组合 2、组合 3 中独立呈现）
  - `Card S`（竖条节拍器，组合 1 最右列、组合 2 第 3 列）
  - `Card B`（标准节拍器，独立成列时）
  - `Card D5`（今日练习大卡，组合 2、组合 3 超界扩展列）
  - `Card Q`（老师要求卡，独立成列时）
* **顶格通高数学约束方程**：
  $$\begin{cases}
  t(\text{card}) = t(\text{ticket}) & (\Delta t \le 1.0\text{px}) \\
  b(\text{card}) = b(\text{ticket}) & (\Delta b \le 1.0\text{px}) \\
  h(\text{card}) = H & (\Delta h = |h(\text{card}) - H| \le 1.0\text{px})
  \end{cases}$$

### 1.3 行内共处 / 复合列卡片的高度分配律（分同一行的 $H$）
当一列中包含上下两层卡片时，列总高必须等于 $H$，两层卡片高度之和加上行间隙必须严格封闭等于 $H$。

#### 1. 组合 1 中轴复合列（上：仪表盘 A，下：今日时长卡 D + 记录小卡 R 并排）
* **结构形态**（严格遵循 `参考图文字基线-261012.md` image23）：
  - 上层：仪表盘 `Card A`，高约 $0.56 H$，宽:高约 $1.2 \sim 1.3$；
  - 间隙：$\text{gap}_y = 12\text{px}$（或 $16\text{px}$）；
  - 下层：左边为今日时长卡 `Card D`，右边为记录小卡 `Card R`，两者**等高同宽**并排卧底，高约 $0.41 H$。
* **高度分配约束方程**：
  $$\begin{cases}
  t(A) = t(\text{ticket}) \\
  h(A) + \text{gap}_y + h(\text{bottom}) = H \\
  t(\text{bottom}) = t(A) + h(A) + \text{gap}_y \\
  b(\text{bottom}) = b(\text{ticket}) \\
  t(D) = t(R) = t(\text{bottom}) \\
  b(D) = b(R) = b(\text{ticket}) \\
  h(D) = h(R) = h(\text{bottom}) \\
  w(D) = w(R) = \frac{w(\text{col}) - \text{gap}_x}{2}
  \end{cases}$$
* **实测像素分配（1133 档，以 $H=559\text{px}$, $\text{gap}_y=12\text{px}$ 为例）**：
  - 仪表盘 $h(A) = 315\text{px}$（占 $56.4\%$，宽 $460\text{px}$，宽高比 $460/315 = 1.46$）；
  - 下部卧卡 $h(\text{bottom}) = 559 - 315 - 12 = 232\text{px}$（占 $41.5\%$）；
  - 时长卡与小卡尺寸：各宽 $224\text{px}$，高 $232\text{px}$，两卡顶部 $t = t(\text{ticket}) + 327\text{px}$，底部对齐 $b = t(\text{ticket}) + 559\text{px}$。
* *(注：在 1280 档 $H=654\text{px}$ 时，对应 $h(A) = 370\text{px}$, $\text{gap}_y=16\text{px}$, $h(\text{bottom}) = 268\text{px}$)*。

#### 2. 组合 3 复合列（上：标准节拍器 B，下：今日时长卡 D）
* **高度分配约束方程**：
  $$\begin{cases}
  t(B) = t(\text{ticket}) \\
  h(B) + \text{gap}_y + h(D) = H \\
  t(D) = t(B) + h(B) + \text{gap}_y \\
  b(D) = b(\text{ticket})
  \end{cases}$$
* **实测像素分配（1133 档，以 $H=559\text{px}$, $\text{gap}_y=12\text{px}$ 为例）**：
  - 节拍器卡片 $h(B) = 372\text{px}$（占 $66.5\%$）；
  - 时长卡片 $h(D) = 559 - 372 - 12 = 175\text{px}$（占 $31.3\%$）；
  - 底边对齐 $b(D) = b(\text{ticket})$。

### 1.4 内部内容消化机制（留白 / 内部滚动 / 截断）
卡片外容器尺寸由外层网格严格锁定（`box-sizing: border-box; overflow: hidden;`），严禁被卡片内部内容向外撑开！

1. **留白与弹性压缩策略**：
   - 仪表盘主体：大表盘、波形、操作按钮采用 flexbox 纵向居中或比例缩放，在 $h=315\text{px}$ 与 $h=559\text{px}$ 时均能优雅展示，下留白保持在 $8\text{px} \sim 16\text{px}$。
2. **内部纵向滚动策略（Internal Scroll）**：
   - 练习记录小卡 $R$、大卡 $D5$、老师要求卡 $Q$：当条目超出卡框内部可视区域时，必须将其列表容器声明为：
     ```css
     .card-scroll-body {
       overflow-y: auto;
       overscroll-behavior: contain;
       scrollbar-width: thin;
     }
     ```
   - 任何滚动条仅局限于卡片内容区域，卡片外框边界纹丝不动。
3. **截断与隐藏策略**：
   - 所有卡片自带的独立 Demo 脚手架（如顶部测试条、独立视口切换栏、mock 控制按钮）一律强制注入 `display: none !important;`，绝不允许出现在集成舞台中占用高度。

### 1.5 根除高度回环（Height Loop Prevention）
在旧版中出现的严重 bug：`iframe.clientHeight` 恒等于 `canvasDoc.scrollHeight`，造成了高度双向回灌与布局失控。

* **禁止规则**：
  1. **单向驱动原则**：外层宿主页面（或舞台）决定 iframe 的视口高度，iframe 严禁由内联脚本读取自身子 DOM 的 `scrollHeight` 后写回 `iframe.style.height`。
  2. **卡片高度参照左栏票卡**：右栏卡片高度 $H$ 只能单向同步 `.pk-ticket` 的真实高度，或者由全局注入的 CSS 变量 `--cz-card-height: 559px`（1133档）直接统一设定。
  3. **模块挂载不变性**：
     - 在挂载 0 个、2 个或全部 6 个模块时，左栏票卡的高度 $h(\text{ticket})$ 漂移量必须 $\le 1.0\text{px}$。
     - 画布文档的 `documentElement.scrollHeight` 必须真实反映实际内容总高，**不得与 `iframe.clientHeight` 恒等**。

## 3. 一屏右界与水平滑动范围

### 3.1 一屏物理右界定义（PDF 顶栏原话）
> “不论什么视口，如下虚线就是整个页面最右侧位置，过了此线右侧内容需要滑动才能查看”

在 1133px 视口宽度下，考虑外层容器边距（左右 padding 各 24px），有效开屏可视内容区域为 **1085px**。舞台左边缘 $X_0 = 24\text{px}$，因此一屏最右界物理 X 坐标为：
$$X_{\text{screen\_right}} = 24 + 1085 = 1109\text{px}$$

### 3.2 各组合右界落点与滑动范围矩阵

```
组合 1 (100% 一屏收拢):
[票卡 360] 16 [仪表盘 460 / 时长+记录 460] 16 [竖条节拍器 130] ┆ (一屏虚线 X=1109)
总宽 982px  <  1085px  ==>  【无需任何横滑，0 超界】

组合 2 (右侧超界横滑):
[票卡 360] 16 [仪表盘 430] 16 [竖节拍 76] ┆ 16 [今日练习大卡 D5: 360px]
前三列总宽 898px  <  1085px (竖条在虚线内)   ┆  超界总宽 1274px  ==>  【超界 189px，需右滑查看】

组合 3 (右侧超界横滑):
[票卡 360] 16 [仪表盘 430] 16 [节拍/时长 340 ┆ 约97px截断] 16 [今日练习大卡 D5: 360px]
前三列总宽 1162px (虚线切在第3列右部)      ┆  超界总宽 1538px  ==>  【超界 453px，需右滑查看】
```

| 组合名称 | 一屏内可见列 | 一屏内宽度 (px) | 超界扩展列 | 轨道总宽度 (px) | 超界量 (px) | 水平滚动行为 |
|---|---|---|---|---|---|---|

## 4. 验收判据（价签式实测标准）

所有前端验收必须基于真实 DOM 计算样式与 `getBoundingClientRect()` 读数，不接受任何文字描述类通过。

### 判据 1：顶格通高卡片绝对等高断言（Pass/Fail）
- **对象**：组合 2 中的 $A$ / $S$ / $D5$、组合 3 中的 $A$ / $D5$、组合 1 中的 $S$。
- **判据公式**：
  $$\Delta h = |h(\text{card}) - h(\text{ticket})| \le 1.0\text{px}$$
  $$\Delta t = |t(\text{card}) - t(\text{ticket})| \le 1.0\text{px}$$
  $$\Delta b = |b(\text{card}) - b(\text{ticket})| \le 1.0\text{px}$$
- **要求**：实测误差必须在 $\pm 1.0\text{px}$ 亚像素容差内。

### 判据 2：复合列上下封闭等高断言（Pass/Fail）
- **对象**：组合 1 中轴列（$A$ + 卧底 $D, R$）、组合 3 复合列（$B$ + $D$）。
- **判据公式**：
  - 顶边对齐：$|t(\text{top\_card}) - t(\text{ticket})| \le 1.0\text{px}$
  - 底边对齐：$|b(\text{bottom\_card}) - b(\text{ticket})| \le 1.0\text{px}$
  - 高度闭环：$|h(\text{top}) + \text{gap}_y + h(\text{bottom}) - h(\text{ticket})| \le 1.0\text{px}$
  - 并排底卡：$|t(D) - t(R)| \le 1.0\text{px}$ 且 $|h(D) - h(R)| \le 1.0\text{px}$ 且 $|b(D) - b(\text{ticket})| \le 1.0\text{px}$

### 判据 3：根治高度回环断言（Pass/Fail）
- **判据条件**：
  1. `canvasIframe.clientHeight !== canvasDoc.documentElement.scrollHeight`（不得双向恒等绑定）；
  2. 在挂载 0 个模块（combo=off）、挂载组合 1、挂载组合 2 时，左栏票卡高度 $h(\text{ticket})$ 浮动必须 $\le 1.0\text{px}$；
  3. 卡片外层不存在随窗口 resize 反复振荡的动态 inline style 高度计算。

### 判据 4：模块可见性与实例唯一性断言（Pass/Fail）
- **判据公式**：
  ```javascript
  const actualVisible = Array.from(document.querySelectorAll('.cz-mod:not([style*="display: none"])'))
                             .map(el => el.dataset.mod).sort();
  const expectedVisible = state.mods.slice().sort();
  assert.deepStrictEqual(actualVisible, expectedVisible);
  ```
- **要求**：每个模块 DOM 实例数 $\equiv 1$，严禁出现未勾选模块隐藏失败或残留在 DOM 树第二排游离排布的情况。

### 判据 5：一屏右界与滑动行为断言（Pass/Fail）
- **组合 1**：容器 `scrollWidth <= clientWidth + 1.0px`，不可横滑；
- **组合 2 / 3**：容器 `scrollWidth >= clientWidth + 150px`，能够产生有效横向滚动位移。
