## 1. 横向一屏空间预算表 (iPad 横屏 1133 × 744)

### 1.1 视口与净空间核算
- **物理视口**：`1133px × 744px`（iPad mini / Air / Pro 横屏标准 CSS 像素）。
- **可用空间扣除**：
  - 左侧常驻导航 Rail：`64px`（收起态，仅图标）；
  - 全局安全留白与内边距：左右各 `16px`，上下各 `16px`；
  - **净工作画幅**：**宽 1037px × 高 712px**。

### 1.2 空间分配与模块布局表（非对称双栏：左信息 350px / 右主控 667px）

| 屏区 / 栏位 | 模块内容 | 宽 × 高预算 | 字号与字重上限 | 能否一屏闭环证据 (不滚动) |
|---|---|---|---|---|
| **左栏 (350px)** | **模块 2：选科目**<br>(收拢态 / 展开态) | `350px × 56px`<br>(展开弹层最大 240px) | 科目名 16px/600<br>标签 12px/500 | 默认选中收拢态仅占 56px；展开选择浮层采用绝对定位覆盖，不挤占页面垂直流。 |
| **左栏 (350px)** | **模块 3：老师要求**<br>(Q4 明确一直展开常驻) | `350px × 260px` | 标题 13px/600<br>正文 **16px/400** (行高 1.6)<br>强调数据 18px/700 | 260px 高度可容纳 6 行 16px 苹方大字，双手持笛 60cm 距离清晰可读，彻底淘汰滚动框。 |
| **左栏 (350px)** | **模块 5：今日记录**<br>(Q10 折叠条入口) | `350px × 48px` | 标题 13px/500<br>统计数 14px/700 | 常态作为紧凑状态条（`今日已练 2 次 · 25 分钟 >`），点击弹层浮窗展示明细。 |

| **右栏 (667px)** | **中央主视觉预留**<br>(Phase 1 节拍器 / Phase 2 3D) | `667px × 240px` | 节拍律动 28px/700<br>提示 12px/400 | 为 Phase 2 3D WebGL 预留独立层容器；Phase 1 承载 2D 钟面与随 BPM 摆动的节拍游标。 |

| **右栏 (667px)** | **刻度尺计时器 + 开始**<br>(现役核心件整合) | `667px × 270px` | 倒计时 **72px/500**<br>步进 20px/700<br>CTA **18px/700** | 72px 滚轮数字 + 32px 刻度尺 + 48px 高珊瑚红开始大按钮。左右步进键扩充为 44×44px。 |
| **右栏纵向预算** | **留白与间距** | 模块间距 `16px × 2 = 32px` | — | **右栏总高度**：`240 + 140 + 270 + 32 = 682px`（完美嵌入 712px，**0 滚动闭环**）。 |

### 1.3 响应式降级策略
- **iPad mini 竖屏 (744 × 1133)**：双栏转单列纵向流。主视觉缩减至 180px，自上而下：科目收拢条 (48px) → 老师要求 (180px) → 主视觉与刻度尺计时器 (380px) → 速度与内容 (130px) → 今日记录条 (44px)，总高约 850px，竖屏 1133px 下同样**严格一屏闭环**。
- **iPhone (440 × 956)**：极简专注流。主视觉仅保留轻量数字呼吸光晕；老师要求收缩为单行折叠胶囊（点击由底部 Sheet 弹出）；首屏完全留给“刻度尺 + 速度/内容 + 开始按钮”。

## 2. 卡片体系 v2 与主题机制

### 2.1 Token 分层与换肤机制

```
[Level 1: 原始色盘 dizicute 6 色]
#FF6B6B (Primary) | #2C3E50 (Secondary) | #FFF8F0 (Tertiary) | #FFFFFF (Neutral) | #666666 (Muted) | #FF8C5A (Accent)
                          ↓
[Level 2: Alpha 梯级派生]
rgba(Primary, 0.08)  |  rgba(Secondary, 0.06)  |  rgba(Secondary, 0.12)  |  rgba(Primary, 0.35)
                          ↓
[Level 3: 语义 Token (CSS 变量)]
--surface-card       : #FFFFFF
--surface-subtle     : rgba(255, 107, 107, 0.04)
--border-card        : rgba(44, 62, 80, 0.08)
--border-active      : #FF6B6B
--text-main          : #2C3E50
--text-muted         : #666666
--interactive-cta    : #FF6B6B
--interactive-text   : #FFFFFF
```

- **换主题机制 (Zero-Code-Change Theme Switching)**：
  页面所有 HTML 模块与 CSS 规则**绝对不直接写 Hex**，仅消费 Level 3 语义 Token。换配色主题时，只需在根节点切换属性（如 `<body data-theme="dizicute">` 或 `data-theme="nordic-wood">`），由外置主题 CSS 覆盖一组变量映射，模块组件、布局代码与 JS 状态机 **0 行修改**。

### 2.2 基础卡片类规范 (Base Card Specs)
- **容器与背景**：`background: var(--surface-card, #FFFFFF);`，页面底色强制为 `var(--tertiary, #FFF8F0)`。
- **圆角**：统一为 `16px`（标准卡片）与 `20px`（右侧中央主交互仪表）。
- **边框与阴影**：
  - 边框：`1px solid var(--border-card, rgba(44, 62, 80, 0.08))`（彻底废止黄色 `#F0D060` 描边）；
  - 阴影：`box-shadow: 0 4px 16px rgba(44, 62, 80, 0.04), 0 1px 2px rgba(44, 62, 80, 0.02);`（自然漫反射，无脏感）。
- **内边距**：紧凑卡 `16px`，主操作卡 `20px 24px`。
- **分隔方式**：卡片内部段落采用 `1px solid rgba(44, 62, 80, 0.06)` 浅细线，或直接靠 12px 负空间留白，坚决去除杂色斑马线与虚线。

### 2.3 状态矩阵与触控反馈

| 状态 | 表现规范 (视觉 + 触控) | CSS 实现标准 |
|---|---|---|
| **默认 (Default)** | 白底、浅灰描边、文字为 `#2C3E50` | `border: 1px solid var(--border-card); background: #FFF;` |
| **选中 (Selected)** | 2px 珊瑚红边框、淡红高光底晕、主文字加粗 | `border: 2px solid #FF6B6B; background: rgba(255,107,107,0.03);` |
| **按压 (Active)** | 整体等比微缩、触觉反馈（无延迟） | `transform: scale(0.98); transition: transform 70ms ease;` |
| **禁用 (Disabled)** | 透明度降级、禁止点击，下方附带说明文字 | `opacity: 0.42; pointer-events: none;` |
| **焦点 (Focus-Ring)** | 恢复系统级外发光无障碍环 | `outline: 2px solid #FF6B6B; outline-offset: 2px;` |
| **长文 (Overflow)** | 标题截断省略；要求正文限制行高与淡出渐变 | `text-overflow: ellipsis; white-space: nowrap;` |
| **空态 (Empty)** | 居中浅灰字体，展示默认预设占位说明 | `color: #666666; font-size: 13px; text-align: center;` |

## 3. 模块 1 与 模块 2 落地方案

### 3.1 模块 1：卡片规范落地对照板（Component Spec Sheet）

在重构代码落地前，单独提供一份 `card-spec.html` 独立对照 Demo，统一过目以下基础交互件：
1. **基础卡片容器**：展示三种标定尺寸（小 350×56、中 350×260、大 667×270）在暖白底上的质感。
2. **三档音符选择器**：`♩`（四分）、`♪`（八分）、`♬`（十六分）分段胶囊，单格触控区锁死 `44×44px`。
3. **BPM 步进器**：左右实体圆形按键（44×44px，文字居中）+ 中央等宽数字槽（22px，支持手动微调）。
4. **内容胶囊 Tag**：单行自适应胶囊、折行展示规范、溢出截断（24字极端长文本处理示范）。
5. **CTA 大按键**：未就绪态（禁用附原因文字：“请选择练习内容”）与已就绪态（珊瑚红实体渐变）。

### 3.2 模块 2：选科目交互方案 (对齐 Q8 拍板规则)

#### 排序规则与数据过滤红线
1. **默认排布顺序**：
   - 第一顺位：**本周老师要求中包含的科目**（提取自 `weekly_assignments`，标记为高亮任务）；
   - 第二顺位：最近练习过且在用的科目（前 3 次活跃）；
   - 第三顺位：其他在用科目（共 10 个在用科目）；
   - 第四顺位：归档科目（37 个）。**严格不过滤**，保留选练权限。
2. **归档科目处理**：默认折叠在列表底部独立分组 `已归档项目 (37)`，卡片文字带删除线弱化，右上角带灰底 `已归档` 药丸标签。
3. **搜索框取舍**：在用科目极少，常驻大搜索框完全浪费空间。仅在展开选科目浮层时，顶部放置一个极简微型过滤器（点击放大镜展开，纯文本实时过滤）。

## 附录 · Hermes 复核（2026-09-20）

### 1. 空间预算算术核对（成立）
- 净画幅：1133 − 64（左侧 rail，收起态）− 16 − 16 = **1037**；左栏 350 + 右栏 667 + 栏间 16 ≈ **1033**，不溢出不滚动 ✓
- 左栏纵向：56 + 260 + 48 + 16×2 = **396 / 712** ✓（留白充裕）
- 右栏纵向：240 + 140 + 270 + 16×2 = **682 / 712** ✓（余 30px）
- 注：1133 > 1099 断点，所以横屏确实走左侧 rail（竖屏 744 走汉堡抽屉）——前提成立，但**rail 实际宽度要在实现时按 `_sidebar` 真实值校准**（本次按 64px 估）

### 2. 必须改一处：老师要求区「260px 装不下极限态」
Q4 拍的是「练习中也要**一直展开显示原文**、字要大」。而数据实测要求正文**最长 175 字且含换行**（一个 stage 最多 8 个科目要求）。
在 350px 宽、正文 16px 行高 1.6（≈25.6px/行）下，175 字约需 **9 行 ≈ 230px**，再加标题栏与内边距，**260px 不够**；agy 自己写的"可容纳 6 行"只覆盖了常规长度。
三种解法（**需 dad 拍**）：
- A 要求区拿到更大配额（比如右栏让 40–60px 给左栏，或要求区 300–320px 高）
- B 常态 260px + 超出时**在卡片内滚动**（违背"一屏不滚动"，但不破坏整体布局）
- C 常态 260px + 超出时**点开全屏阅读层**（modal/drawer），练习中一键呼出

### 3. 必须改一处：归档科目不要用删除线
agy 建议归档科目「文字带删除线弱化」，但 dad 的规则是**归档科目仍可能被选中练习**（只是要标识）。删除线会读成"已删除/不可用"。改为：灰底 + `已归档` 药丸标签 + 排在第四顺位分组，文字**不加删除线**。

### 4. 其余与 dad 拍板一致，可直接进 demo
- 三档音符 ♩ / ♪ / ♬（32 分音符已作废，dad 更正）
- 一屏闭环 + 浮层/抽屉承载展开态（不挤压主流程）
- token 三层（原色 → alpha 派生 → 语义变量）+ `data-theme` 换肤（模块 0 行改动）
- 状态矩阵含按压/焦点/禁用/空态；触控目标 ≥44px
- 选了科目后**自动收拢 + 默认选中第一顺位科目**（= 老师要求科目），开机即就绪态

### 5. agy 自己的 3 个待确认点（已并入下面提问）
1. 多速度段科目：右侧速度组件默认回填第一条的 `bpm_max`，还是让孩子自己点选速度段？
2. Phase 2 的 3D 容器：固定 240px 环境层，还是要支持全屏放大？
3. 今日练习记录展开：左/下滑出的轻量 Drawer？
