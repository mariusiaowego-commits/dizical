## 1. 现状模块关系与动线诊断

### 1.1 真实练习 Flow 与界面位置对应表

| 步骤 | 业务动作 | 当前代码位置 | 当前界面屏幕区域 | 交互与视觉分散痛点 |
|---|---|---|---|---|
| **Step 1** | **选科目** | `practice.html:1088-1119` (`.item-section`) | 屏幕最顶端（占大半屏） | 10个在用科目与37个归档平铺，3D大按钮占满首屏；点选后触发高度收缩动画，整个下部界面剧烈上移跳跃。 |
| **Step 2** | **确认/调整速度** | `practice.html:1171-1188` (`.sp-tempo-row-1`) | 屏幕中下方（`.session-panel` 内） | **动线第一次大跳跃**：选完科目后视线必须跳过中央计时器，落到下方去点选 ♪/♩ 与 BPM。细线边框弱化，缺乏与科目的视觉关联。 |
| **Step 3** | **选练习内容 (Session标签/自填)** | `practice.html:1189-1191` (`#sessionContentTags` + 输入框) | 屏幕更下方（最底部） | **最严重卡点**：点科目会清空输入框；若未选标签，下方的输入框为空，导致上方的“开始”按钮静默置灰，但此处与开始按钮物理距离极远，无联动提示。 |
| **Step 4** | **刻度尺拉时间** | `practice.html:1143-1160` (`#timerCard` 内部刻度尺) | 屏幕中央偏上（折返向上） | **动线严重折返跑**：填完底部的速度与内容后，孩子必须双手持笛**往回找**屏幕中央的刻度尺去滑动或点按 ±1 步进。 |
| **Step 5** | **开始练习** | `practice.html:1162` (`#startBtn`) | 刻度尺正下方（中央偏下） | 终于回到中央点按“开始”。一旦漏了 Step 3，点按无反应。 |

> **核心诊断**：当前动线呈现 **“顶部(选科目) → 底部(选速度/内容) → 中央(折返拉刻度尺) → 中央(点开始)”** 的 Z 字形折返跳跃。在 iPad mini (744×1133) 竖屏下一臂距离（~60cm）操作时，手指必须跨越大半个屏幕反复折返，极易误触或遗漏。

### 1.2 逐模块现状问题诊断（面向 7 岁儿童早读双手持笛场景）

1. **科目选择区 (`.item-section`, L1088)**
   - *问题*：占用面积过大（高 300px+），采用笨重 3D 拟物按钮，收拢后左侧 2:8 结构与 AI 流式心情文本占用额外空间。
   - *影响*：持笛孩子需要低头大面积寻按；收拢动画导致界面抖动，且流式生成的心情文本对 7:15 争分夺秒的早读完全无意义。
2. **黑底渐变仪表盘 (`.dash-card-inline`, L1137)**
   - *问题*：黑底渐变 (`#2C3E50→#34495E`) + 亮黄 `#FFD93D` + 橙色 `#FF8C5A`，纯文字冷硬展示。
   - *影响*：与 dizicute 温暖浅色基调彻底冲突，且重复展示科目名与要求，纯粹浪费首屏纵向空间（~80px）。
3. **已废弃补录模块 (`#tabExtra`, L1195)**
   - *问题*：外置一级切换 Tab，内部塞入 Dial Knob + Activity Wheel + 独立 Session Panel。
   - *影响*：带来大量冗余代码，孩子容易误触 Tab 导致主练习界面丢失。
4. **参数录入区 (`.session-panel`, L1169)**
   - *问题*：细线边框（`1px solid #E0D0A0`）显得单薄廉价；iPad mini 竖屏下被挤到计时器下方。
   - *影响*：站立视线下细线很难看清选中态；音符缺少 32 分音符；内容标签多行时排版拥挤破位。

## 2. 卡片样式与视觉风格方向

### 2.1 基础卡片规范 (Base Card Tokens)

严格锁定 `DESIGN.md` dizicute 6 色体系与尺度：

| 属性 | 具体数值 / Token | 说明 |
|---|---|---|
| **底色 (Background)** | `neutral: #FFFFFF` | 纯白卡片，置于 `tertiary: #FFF8F0` 暖白页面背景之上 |
| **圆角 (Border Radius)** | `lg: 16px` (通用卡片) / `20px` (主交互仪表卡) | 避免硬角，柔和且符合 iPadOS 触控规范 |
| **边框 (Border)** | `1px solid rgba(44, 62, 80, 0.06)` | 摒弃原有的泛黄粗线 `#F0D060`，改用极淡的 secondary 灰度描边 |
| **投影 (Box Shadow)** | `0 4px 20px rgba(44, 62, 80, 0.05), 0 1px 3px rgba(44, 62, 80, 0.03)` | 双层漫反射浅阴影，提升卡片悬浮感，不显脏 |
| **内边距 (Padding)** | `16px 20px` (紧凑卡) / `22px 24px` (中央计时主卡) | 留白充足，避免密集压迫 |
| **标题字体 (Title)** | `16px`, `font-weight: 600`, `color: #2C3E50` | 苹方中黑，字号克制 |
| **状态高亮 (Selected)** | `border: 2px solid #FF6B6B; background: rgba(255, 107, 107, 0.03);` | 仅靠 primary 珊瑚红点缀，不引入外部强调色 |
| **禁用态 (Disabled)** | `opacity: 0.4; cursor: not-allowed;` | 统一半透明降级 |

#### 方向 A：柔和有机色块卡片风（Warm Pastel / Organic Soft Cards）
- **参考来源**：参考 1 (Intelly) + 参考 3 (移动端卡片)
- **视觉特征**：以大圆角白卡为底，局部使用极淡的 dizicute 品牌色弱透色块（如作业卡底色 `rgba(255,107,107,0.04)`、进度底色 `rgba(44,62,80,0.03)`）。界面平静温馨，完全去除了 3D 按钮的机械冷硬感。
- **适合板块**：科目选择卡、老师要求卡、今日记录卡。
- **代价**：改动成本最低，纯 CSS 升级，与现有 dizicute 规范 100% 吻合。

### 2.3 沉浸式 3D 主视觉（参考 4 / 参考 5）：本期做还是拆到后续？

**结论：坚决拆分到后续 Phase 2 单独立项，本期不在练习页引入真实 WebGL / 3D 渲染场景。**

**理由与代价分析**：
1. **资产与建模成本巨大**：现有科目 10 个（归档 37 个）。若实现“当前科目的 3D 交互场景，每次练习增添新可交互元素”，需要为每个科目制作 3D 模型资产（笛子内部气流、音孔、指法、竹林场景等），目前 dizical 仓库**零 3D 资产储备**。
2. **后端与数据模型完全缺失**：现有数据库仅有 `daily_practices` 扁平记录，没有“场景资产状态表”、“交互解锁树”等任何数据支撑，贸然引入会导致前端空转或假数据写死。
3. **早晨 7:15 练笛的可用性红线**：7 岁孩子站在 iPad mini 前，系统首要指标是 **0 秒冷启动、无延迟响应、绝对不白屏崩溃**。移动端 WebGL 上下文常因内存释放崩溃，严重阻碍打卡主链路。
4. **本期务实替代方案（保留参考 5 的精髓）**：
   - 提取参考 5 的核心：“以刻度尺为界面的大型计时器 + 代表速度的节拍器”。
   - **用轻量 CSS/SVG 动效替代 3D 建模**：让刻度尺在计时过程中伴随 BPM 频率产生微小的指针节奏摆动或音符粒子律动。既能呈现“主视觉随动作变化”的仪式感，又保持极佳的性能。

## 3. 逐模块重构方案（对齐 MRD 2.2.1 - 2.2.5）

### 3.1 [2.2.1] 选科目模块：纵向卡片分组 vs 搜索框下拉

- **真实数据支撑**：在用科目仅 **10 个**，归档 37 个，分类主要为“基本功”与“曲子”，科目名最长 10 字。
- **方案对比与取舍**：
  - *搜索框下拉*：**不采纳**。7 岁孩子早读单手握笛，在虚拟键盘打字搜索是极大阻碍；且 10 个科目完全无需通过搜索过滤。
  - *分类标签 + 纵向紧凑卡片列（推荐）*：
    - 顶部设分类 Pill（`全部 (10)` / `基本功 (6)` / `曲子 (4)`），高度 32px。
    - 卡片采用 2 列紧凑网格（iPad mini 竖屏）或纵向列表，单卡高度锁 `52px`。
    - 卡片仅展示：科目名（15px 加粗）+ 老师要求状态点（若有要求显示小红点）；彻底去掉厚重的 3D 阴影。
    - **选中后交互**：选中后列表平滑收起为高 52px 的“当前科目栏”，右侧放 `[更换科目]` 胶囊按钮，不引起下方组件大面积跳跃。

---

### 3.2 [2.2.2] 老师要求（Assignments）卡片

- **设计要求**：信息不能丢、字不能太小、练习中也能看。
- **方案设计**：
  - **位置**：置于科目收拢栏正下方、计时器正上方（黄金视觉层），成为每次练习的指引牌。
  - **卡片形态**：
    - 白底浅描边卡片，左侧有 3px 珊瑚红强调坚条。
    - 标题栏：`本周老师要求` (13px, `#666666`) + 示范视频入口 Chip。
    - 正文区：字号提升至 **16px**（PingFang SC Regular, 行高 1.6, 颜色 `#2C3E50`），双手持笛站立一臂距离时清晰可读，不缩在滚动小框内。
    - 极限文本处理：超过 3 行默认展示前 3 行，右下角提供轻量展开箭头，不撑爆首屏。

---

### 3.3 [2.2.3] 速度 + Session 标签录入区

- **设计要求**：重设计细线边框、**增加 32 分音符**、应对标签极限多（2行/24字）、输入框重设计。
- **方案设计**：
  1. **速度选择器重构**：
     - 去除奇怪细线，改用内嵌式分段胶囊（Segmented Pill）。
     - 音符增加至 3 档：`♪ 八分` (U+266A) / `♩ 四分` (U+2669) / `𝅘𝅥𝅯 三十二分` (U+1D161)，字号 18px，选中项底色为 `#FF6B6B` 白字。
     - BPM 步进器改为一体化圆角框（高度 40px），中间显示数字 `80`（20px 加粗，等宽数字），两端是大热区 `−` 与 `+`（40×40px，符合触控标准）。
  2. **Session 标签极限排版**：
     - 针对单科目最多 9 个标签、最长 24 字的现实：采用流式换行胶囊（Flex-wrap），间距 8px。
     - 单标签高度统一为 34px，内边距 `6px 14px`，圆角 17px。
     - **超长标签处理**：单标签最大宽度设为 `260px`，超出部分文本省略（`text-overflow: ellipsis`），长按或选中后完整展示。
     - **核心体验修复**：选中科目后，**默认高亮选中第 1 个标签**并同步填入输入框，彻底消灭开始按钮“无故置灰”问题。
  3. **自填输入框 Field**：
     - 去除原生灰色 input 框，改用规范卡片式输入条：高度 42px，白底，圆角 12px，描边 `1.5px solid rgba(44,62,80,0.12)`，带清除小叉号。

---

### 3.4 [2.2.4] 刻度尺计时器：融入控制台与主视觉

- **设计要求**：刚上线不大改，主要调整卡片化，作为中央主交互件融入整体风格。
- **方案设计**：
  - **外壳卡片化**：去除现有代码里的黄底与黄色细线（`#F0D060`），改为基础卡片规范的白底双层微阴影容器。
  - **组件布局一体化**：
    - 上部：`00:00` 滚轮翻牌大数字（72px）+ 居中状态胶囊。
    - 中部：保留 1-30 分钟刻度尺与红针，两侧保留 ±1 步进按钮（加大至 40×40px 防按空）。
    - 下部：打卡主 CTA 按钮（高度 48px，大圆角 24px，珊瑚红底 `#FF6B6B`，白色 18px 粗体短文字“开始练习”）。
  - **视觉律动融入**：计时器背景增加极淡的半透明同心波纹（随当前 BPM 频率呼吸微动），在不引入 3D 资产的前提下达成沉浸交互感。

---

### 3.5 [2.2.5] 今日练习记录模块

- **方案设计**：
  - 彻底废除原底部粗暴的大号渐变横幅 `#todaySummaryBar`。
  - 整体降级为**次屏收拢卡片**（置于中央主卡下方）：
    - 默认折叠态为细长状态条：`今日已练 2 次 · 共 25 分钟  [查看记录 ∨]`。
    - 展开后展示今日各 Session 清单：每个 Session 采用极简双行布局（左侧：时间与科目；右侧：速度与内容；尾部带微型删除/编辑入口）。

## 5. 明确“不要动”清单

1. **打卡链路与接口契约**：
   - `POST /api/log` 接口定义及传参（`date, item, item_id, minutes, tempo_note, tempo_bpm, content, practice_at`）。
   - `practice_at` 严格在前端生成 CST 字符串，后端 UPDATE 永远保留首次练习时间戳。
   - 速度与练习内容后端非空必填校验不变。
2. **单一页面路由**：保持单一路由 `/practice`，不可拆分为向导步进式多 URL。
3. **刻度尺核心联动与测试契约**：
