### Q3 老师要求（assignments）的**录入格式**要不要顺手规范化？

**背景**：我把最近 29 条老师要求全查了一遍，数据里有两套并存的毛病：
- 字段名不统一：同一条记录里出现过 `requirement`（49 次）和 `requirements`（57 次）两种键
- 速度信息两边都放：既在 `metronome` 字段里，又在正文里写一遍，写法五花八门，实际抓到的 5 种：

```text
♩=76 / ♩=60-66           一个字段里塞两个速度
4/4 ♪=80, 2/4 ♪=69-80    按段落分速度
♪=85 ♪=90                 连音符都漏写了
tu ♩=80 / ku ♩=70        按吐音音节分速度
♩=108、♩=112 各3天       速度 + 天数混在一起
```

- 正文最长 **175 字**，带换行；一次 stage 最多 8 个科目要求

如果只在前端做兼容解析，每张卡片都要写一堆容错规则，而且以后录得越乱越难；如果顺手把录入端规范掉（速度单独字段 + 正文纯文字），卡片就能做得很干净。

- A 前后端一起做：先规范录入端（速度/频率拆字段，写法统一），卡片按规范展示
- B 只做前端兼容：不动数据，卡片自己解析各种写法
- C 先用前端兼容，录入端规范化排到下一版

**我的倾向**：A。一次性把脏数据挡住，后面所有模块都省事；代价是要动配置页录入（`weekly_assignments` 相关）。
**你的回答：**
1. `requirement` 和 `requirements` 字段分别都是什么，要先列出来我看下，我才能决定
2. 问题就是现在不是说这是脏数据，的确就是要这样的格式，怎么办呢？有些曲子/科目就是有多种节拍要求
3. 音符漏写了的确是问题，这个提交前要验证
我认为目前的metronome部分就分为几个结构化的数据：
（1）切片/段落 `section` 这里填写的是哪个段落或者片段

### Q5 速度要加 32 分音符，具体怎么加？

**背景**：现在页面只有 ♪（八分）和 ♩（四分）两个按钮，生产数据里也确实只有这两种（♪ 用了 733 次、♩ 55 次）。你说要再加 32 分音符。要定三件事：①32 分音符用哪个字符（音乐补充区的符号在很多设备上缺字形，会显示成白框，项目以前踩过）；②加完之后"默认速度"从哪来（现在顺序是 老师要求 → 上次练习 → 系统默认）；③"必填校验"要不要跟着改（见 Q6）。

- A 加一个按钮，三档并排：♩（四分）/ ♪（八分）/ ♬（十六分，用普通字符保证不白框）
- B 加两档：十六分 + 三十二分（你原话是"其实还有 32 分音符"，需要确认 16 分现在算不算已覆盖）
- C 换个思路：不用音符符号，改成文字档位（慢/中/快 或 4分/8分/16分/32分）

**我的倾向**：先确认你现在心里的档位到底有几档（我看到的只有 ♪ 和 ♩ 两种），再定字符；字符优先用设备一定有的普通符号，宁可写"32分"也不要用会变白框的补充区字形。
**你的回答：** A
