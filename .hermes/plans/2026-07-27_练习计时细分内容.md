# 练习计时细分内容与语音录入 Implementation Plan

> **For Hermes:** 本计划只覆盖本地 dizical Web/mac 前端与 Python 后端；先完成可行性 Spike，再按任务逐步实现、测试和真机验证。

**Goal:** 让每一次练习计时都记录“练了什么内容 + 练习速度”，并在当天记录中按计时 session 展示；内容支持按住语音按钮录入，语音服务可替换且有 Hermes/Portal 降级路径。

**Architecture:** 保留现有 `daily_practices` 作为每日汇总和兼容接口，新增规范化 `practice_sessions` 作为每一次计时的事实表。一次计时完成后，在同一 SQLite 事务内写入 session、更新每日汇总，并追加行为审计；查询接口同时返回旧 `items` 和新的 `sessions`。语音采用浏览器 `MediaRecorder` → FastAPI `UploadFile` → 独立 transcription adapter 的边界，不能把 Hermes CLI 的私有实现直接混进业务模块。

**Tech Stack:** 现有 FastAPI + SQLite + 原生 HTML/CSS/JavaScript + MediaRecorder；不新增 Python/前端依赖。UI 按 waza-ui 现有 dizical token 和“弱化 CTA、SVG icon、braille loading、按一次一验证”规范实现。时间记录模型参考 ActivityWatch 的 event/bucket 思路，业务 session 录入参考 Kimai 的 timesheet entry 思路，但不复制它们的代码或引入依赖。

## 1. 数据模型：新增 session 事实表，保留旧汇总

### 任务 1.1：设计 `practice_sessions` schema

**Create:** `src/migrate_add_practice_sessions.py`

建议字段：

```sql
CREATE TABLE practice_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    practice_date DATE NOT NULL,
    item_id INTEGER NOT NULL,
    item_name TEXT NOT NULL,
    duration_minutes INTEGER NOT NULL,
    tempo_note TEXT NOT NULL DEFAULT '♪',
    tempo_bpm INTEGER NOT NULL DEFAULT 80,
    content TEXT NOT NULL DEFAULT '',
    content_source TEXT NOT NULL DEFAULT 'manual',
    started_at TEXT,
    is_extra BOOLEAN NOT NULL DEFAULT 0,
    transcription_provider TEXT,
    transcription_model TEXT,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (item_id) REFERENCES practice_items(item_id)
);
CREATE INDEX idx_practice_sessions_date ON practice_sessions(practice_date);
CREATE INDEX idx_practice_sessions_item_date ON practice_sessions(item_id, practice_date);
```

**约束：**
- `tempo_note` 当前只接受 `♪`、`♩`；后续新增音符只改白名单，不改数据结构。
- `tempo_bpm` 只接受 40–150 的整数，默认 80。
- `duration_minutes` 必须为正整数；正常计时沿用当前最小 1 分钟的行为。
- `content` 是本次练习的细节字段；旧记录没有细节时保存空字符串，并用 `content_source='legacy'` 区分。
- `item_name` 是名称快照，防止科目重命名后历史记录显示失真；统计仍以 `item_id` 为主。
- `started_at` 延续项目 CST 无 `Z` 格式；`created_at` 仍由 SQLite 保存为 DB 写入时间。
- 不把速度和内容塞进 `behavior_log` 或继续扩展 `items` JSON；这些字段需要可查询、可迁移、可独立显示。

### 任务 1.2：迁移旧数据

**Migration behavior:**

- 对每条 `daily_practices.behavior_log` 中有 `item_id/item/minutes` 的 entry 创建一条 legacy session。
- 如果旧行为日志没有 `item_id`，按当时科目名匹配 `practice_items`；无法匹配则不自动伪造 ID，输出迁移告警。
- 旧数据的 `tempo_note`、`tempo_bpm`、`content` 设为 `♪`、80、空字符串；不能把未知信息猜成真实速度或内容。
- 迁移必须幂等：使用 `schema_migrations` 版本或独立 marker，二次运行不能重复生成 session。
- 迁移前生成 SQLite 备份；本地 SQLite 永不删除，失败可回滚到备份。

### 任务 1.3：实现 Database 层 session CRUD

**Modify:** `src/database.py`

新增方法：

- `create_practice_session(...) -> Dict`
- `get_practice_sessions(date, item_id=None) -> List[Dict]`
- `update_practice_session_content(session_id, content, ...) -> Dict`（V1 可不开放 UI，但保留后端能力）
- `delete_practice_session(session_id) -> None`
- `save_practice_session_and_daily_summary(...) -> Dict`

`save_practice_session_and_daily_summary` 必须：

1. 校验 `item_id`、minutes、tempo note、BPM、content 长度。
2. `BEGIN IMMEDIATE`。
3. 插入 session。
4. 更新现有 `daily_practices.items` 的同科目分钟汇总和 `total_minutes`，保持旧成就/报表逻辑可用。
5. 追加包含 `session_id`、`content`、`tempo_note`、`tempo_bpm` 的 behavior entry。
6. 一次 commit；任何一步失败全部 rollback。

删除 session 时也必须在事务内重算对应日的汇总，而不是简单减分钟，避免重复提交/并发删除造成负数或旧 JSON 与 session 不一致。

### 任务 1.4：为数据层写回归测试

**Create:** `tests/test_practice_sessions.py`

至少覆盖：

- 新 session 能保存并返回所有字段。
- 同一科目两次计时生成两条 session，而不是合并成一条。
- 例：西藏舞曲 5 分钟 + 3 分钟，daily total=8，sessions 分别保留两条内容和速度。
- `tempo_note` 非 `♪/♩`、BPM 越界、minutes=0 被拒绝。
- 旧 `daily_practices.items` 仍能被现有查询和成就读取。
- 事务失败时 session 和 daily summary 都不落库。
- legacy migration 幂等，旧行为日志被保留。
- 删除 session 后汇总正确，删除最后一条后当天汇总为 0。

运行：

```bash
pytest tests/test_practice_sessions.py -q
```

## 3. 语音输入 adapter

### 任务 3.1：浏览器录音组件

**Modify:** `src/kid_app/templates/practice.html`

使用原生 `navigator.mediaDevices.getUserMedia({audio: true})` + `MediaRecorder`，不引入录音库：

- 按住开始，松开结束；支持 `pointerdown/pointerup/pointercancel` 和键盘可访问操作。
- `MediaRecorder.isTypeSupported` 选择 `audio/webm;codecs=opus`、`audio/ogg;codecs=opus` 等当前浏览器支持的类型。
- 最长 30 秒；无录音权限、空录音、浏览器不支持时显示明确状态。
- 释放时停止所有 `MediaStreamTrack`，清理 object URL，避免 macOS WKWebView 麦克风资源泄漏。
- 上传完成前允许取消；转写中显示 braille spinner；失败不清空已经手动输入的内容。
- 语音按钮只负责录入内容，不和计时开始/暂停按钮复用状态。

### 任务 3.2：FastAPI 上传端点

**Modify:** `src/kid_app/app.py` 或新建 `src/kid_app/routes/transcription.py`

`POST /api/practice/transcribe`：

- `multipart/form-data` 字段：`audio`、可选 `language=zh`、可选 `provider`。
- 限制 MIME、大小（建议 10 MB）、时长（服务端再次校验）；临时文件使用 `tempfile`，请求结束清理。
- 不把音频永久保存到 `data/`，除非未来明确要求音频归档；默认只存最终文字。
- 返回统一 envelope：

```json
{
  "ok": true,
  "text": "练习第一分句",
  "provider": "local",
  "model": "base",
  "fallback_used": false
}
```

失败返回可展示的 `error_code`，不要把 API key、完整命令行或 provider 内部堆栈返回浏览器。

### 任务 3.3：实现可替换的 transcription service

**Create:** `src/voice_transcription.py`

定义稳定接口：

```python
class TranscriptionProvider(Protocol):
    name: str
    model: str
    def transcribe(self, audio_path: Path, language: str = "zh") -> TranscriptionResult: ...
```

实现顺序由配置决定：

1. Spike 确认可用时：`HermesChatTranscriber`（只走官方稳定音频入口）。
2. 推荐 V1：`HermesSttTranscriber`，通过独立 helper 进程调用 Hermes 的 STT 能力；不要让 dizical import Hermes 内部模块。
3. `Portal/OpenAI` 或 `Groq` fallback。
4. 可选本地 faster-whisper fallback。

配置只读取环境变量/本地配置，不把密钥写入仓库：

- `DIZICAL_TRANSCRIBE_PROVIDER=hermes-stt`
- `DIZICAL_TRANSCRIBE_FALLBACKS=portal,local`
- `DIZICAL_TRANSCRIBE_TIMEOUT_SECONDS=45`

如果独立 helper 必须依赖 Hermes 安装目录，路径通过环境变量传入，不硬编码用户目录；helper 返回 JSON，父进程只解析 stdout，stderr 进日志。

### 任务 3.4：语音服务测试

**Create:** `tests/test_voice_transcription.py`

- 用 fake provider 测试 provider 选择、fallback、超时、错误 envelope，不调用真实模型。
- 测试上传大小/MIME/空文件拒绝。
- 测试音频临时文件最终清理。

## 4. Web/mac 计时 UI（waza-ui）

### 任务 4.1：速度录入区

**Modify:** `src/kid_app/templates/practice.html`

在主计时 picker 内增加一个“本次练习”内容面板，置于开始按钮之前，避免开始后才要求补信息：

- BPM selector：40–150，步长 1，默认 80；沿用项目现有 rotary/wheel 交互或原生可访问 select，不再造新的复杂 picker。

### 任务 4.2：内容录入区

- 文本输入作为可靠 fallback，placeholder 示例“第一分句、长音、指法转换”。

- 不允许把模型输出自动当成最终不可编辑事实；最终保存的是用户确认后的 `content`。

### 任务 4.4：前端验证

## 风险与明确取舍

1. **Hermes chat 不是天然 STT API。** 当前 CLI help 只显示 `--image`，因此不能承诺 MiniMax M2.7 Highspeed 能直接把浏览器音频转文字；必须先 Spike。UI/API 设计成 provider-neutral，避免把不可行的模型调用写死。
2. **不把 session 明细继续放在 `items` JSON。** 现有 save 逻辑会同名累加，必然丢失“第一次 5 分钟/第二次 3 分钟”的边界；新增表是最小且可查询的结构性改造。
3. **不永久存录音。** 需求只需要文字，保存音频会增加隐私、磁盘和清理责任；默认上传后临时转写并删除，未来若需要回放再单独做音频归档设计。
4. **不引入录音/组件依赖。** MediaRecorder、现有 wheel/dial、内联 SVG 已覆盖需求；新依赖需要用户单独批准。
5. **不让客户端直接写行为审计。** `/api/log` 接收业务字段，后端生成 session_id 和审计 entry，保证一次计时的事实完整。
6. **旧数据不猜内容。** 历史记录展示“未填写练习内容”，不把老师要求或日记文本错误复制成某一次计时的细节。
